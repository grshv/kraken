Чтобы `apt-get` ходил через прокси, достаточно одного файла настроек. Адрес
и порт прокси показаны в шапке панели состояния.

## Создать файл настроек APT

На клиенте создайте `/etc/apt/apt.conf.d/95proxy`:

```
Acquire::http::Proxy "http://<kraken-host>:<port>/";
Acquire::https::Proxy "http://<kraken-host>:<port>/";
```

APT передаёт HTTPS-репозитории через CONNECT, поэтому для `https::Proxy`
указывается тот же HTTP-адрес прокси. Машина должна быть описана как клиент
в Kraken, иначе прокси ответит отказом.

## Разрешить домены репозиториев

Во вкладке «Доступ» клиента добавьте домены репозиториев в свои домены или
подключите общую политику с ними. Шаблон «APT Ubuntu»
подставляет типичные домены; для Debian — `deb.debian.org`,
`security.debian.org` и зеркала. Для архитектуры arm64 добавьте
`*.ports.ubuntu.com`. Домены — канонические, без схем и путей; пустой
список означает отсутствие разрешённых ресурсов.

## Проверить

```
sudo apt-get update
```

Если появится ошибка 403, откройте журнал в Kraken: запрос будет там с
причиной отказа. Обычно это домен, которого нет в списке клиента, или адрес
клиента не описан как источник. См. [Разбор отказа в журнале](help:scenario-denied).

## Подписи пакетов

Прокси не вмешивается в подписи: APT проверяет `InRelease` как обычно.
HTTP-репозитории не заменяются на HTTPS автоматически.
