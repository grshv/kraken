Kraken не имеет пароля по умолчанию и не открывает публичную регистрацию.
Первую учётную запись администратора создаёт локальный оператор.

## Создание администратора

После установки контейнера выполните:

```
docker exec -it <контейнер> kraken bootstrap --username admin
```

Команда запускает CLI внутри контейнера и читает пароль через stdin/TTY. Пароль
не попадает в аргументы командной строки, историю shell и `.env`. Сохраняется
только Argon2id PHC-верификатор; исходный пароль не восстанавливается.

Пока администратора нет, панель не принимает вход. Создать второго
администратора через `kraken bootstrap` нельзя: команда срабатывает только
на пустую установку.

## Вход

Откройте адрес панели в браузере. Введите имя и пароль администратора.
Сессия — это opaque cookie `__Host-session` с флагами `Secure`, `HttpOnly`,
`SameSite=Strict`, `Path=/`, без `Domain`. Отдельный CSRF-токен приходит в
ответе `GET /api/v1/session` и обязателен для всех изменений, включая выход.
Браузерный Origin проверяется на каждой мутации.

Предварительные сроки сессии: простой 30 минут, абсолютный — 12 часов.
Logout, блокировка пользователя и смена пароля мгновенно отзывают сессию
на сервере.

## Сброс пароля

Забытый пароль не восстанавливается. Локальный оператор задаёт новый из CLI:

```
docker exec -it <контейнер> kraken password-reset --username admin
```

Команда атомарно меняет верификатор, отзывает все сессии пользователя и
пишет audit-запись без пароля и хэша. Старый пароль не требуется;
уже начавшийся вход не обходит сброс.
