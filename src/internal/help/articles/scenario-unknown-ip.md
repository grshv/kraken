Запрос из адреса, не описанного как клиент, получает отказ: доступ закрыт
по умолчанию. Источник виден в журнале как неописанный.

## Найти источник

В разделе «Журнал» выберите «Неописанные источники». Контрол показывает
IP, количество отказанных запросов за 24 часа и домены, которые он
запрашивал. Это наблюдение завершённых обращений, не online/offline
health.

## Создать клиента из неописанного IP

Из журнала можно сразу создать клиента: IP подставится в адреса источника,
а отказанные домены — в allowlist политики. Проверьте:

- **Тип** — устройство, сеть или группа. Это метка; доступ определяется
  адресами.
- **Адреса источника** — точный IP `/32` или CIDR. Пересечения с
  существующими клиентами запрещены, кроме разных auth usernames за NAT.
- **Политика** — весь веб или список доменов. Если подставлены домены из
  отказов, выбран allowlist; проверьте, что нужны именно они.
- **Transport и логин** — HTTP, либо TLS с логином, если несколько машин
  за одним NAT.

## Проверить адрес

Squid видит source IP, который доходит до прокси. NAT, скрывающий
несколько машин за одним адресом, делает их неразличимыми: для них нужен
логин по TLS. Внутренние адреса (private, loopback, link-local, metadata)
закрыты защитными запретами; клиент с таким source не выйдет в интернет.

## Применить

Сохраните клиента и примените черновик, см.
[Черновик, проверка и применение](help:draft-apply). После применения
запросы из этого адреса пойдут по политике клиента.
