# Данные

Всё постоянное состояние — SQLite на томе `/var/lib/kraken/data`: управляющая БД
`control.sqlite3` ([ADR 0005](../adr/0005-control-database.md)) и телеметрия в
`telemetry/` ([ADR 0011](../adr/0011-telemetry-storage.md)). Производные файлы в
tmpfs пересоздаются из управляющей БД.

## Управляющая БД

| Таблица | Что хранит | Инвариант |
| --- | --- | --- |
| `users` | имя, `password_hash`, роль `admin`/`manager`, `enabled` | Только Argon2id PHC; последний включённый администратор защищён; имена неизменяемы, вместо удаления — блокировка |
| `sessions` | хеш токена, имя, CSRF, срок, `last_seen_at`, `created_at`, адрес, User-Agent | Токен только как хеш; FK на `users` с каскадом; смена пароля, роли и блокировка удаляют сессии |
| `manager_networks` | имя, CIDR | Сети менеджера; FK на `users` с каскадом |
| `manager_clients` | имя, `client_id` | Назначенные клиенты; висячие назначения удаляются при обслуживании |
| `proxy_accounts` | имя, `password_hash`, `enabled`, `owner`, время | Только Argon2id PHC; `owner` — менеджер или `NULL` (администратор) |
| `kv` | ключ, JSON | Черновик, ревизии, журнал применения, LKG, счётчик ревизий |
| `operations` | ID, `idempotency_key` (уникальный), хеш запроса, тело | Один ключ — один запрос; индекс по `revision_id` |
| `audit_events` | ID, автор, действие, `entity_id`, `detail`, время | Без паролей, ключей и тел конфигурации; изменение и аудит в одной транзакции |
| `notification_marks` | ID уведомления, статус, автор, время | Только отметка `seen`/`ignored`; уведомления вычисляются из телеметрии |
| `schema_migrations` | версия, checksum, время | Применённая миграция не меняется |

Ключи `kv`:

- `draft` — черновик (`version` и снимок);
- `revision:<id>` — неизменяемая ревизия с номером `$.number`;
- `revision_seq` — счётчик номеров ревизий;
- `runtime.journal`, `runtime.last_good` — журнал применения и LKG
  ([configuration-lifecycle](configuration-lifecycle.md#журнал-применения)).

Клиенты, сети, политики, домены, подключения и настройки — части снимка, а не
таблицы. Ссылки, пересечения адресов и логинов проверяет `policy.Validate`. Удаление
клиента из черновика не трогает прошлые ревизии и события.

### Аудит черновика

`PUT` и `DELETE /configuration/draft` пишут строку `draft` и по строке на каждого
изменённого клиента и политику (`update_draft`, `discard_draft`) в той же транзакции.
`detail` — суть изменения до 300 символов; у строки объекта — только этот объект,
поэтому менеджер по строкам своих клиентов не узнаёт о чужих. `GET /audit`
фильтрует по `entity_id` (до 256 символов).

### Пароли

`password_hash` — Argon2id PHC; исходный пароль не попадает в снимок, конфиг,
временные файлы, env, argv, логи и аудит. Логин прокси в снимке — только ссылка
`proxy_username`. Helper Squid читает не БД, а экспорт
`/dev/shm/kraken/proxy-accounts.json` (имя и verifier включённых логинов, 0640),
который панель атомарно перезаписывает после каждого изменения и при старте; если
запись не удалась, изменение отвечает 503.

### Параметры SQLite

- WAL, `foreign_keys`, `busy_timeout=5000`, локальная файловая система, без NFS.
- Пул записи: одно соединение, `_txlock=immediate`, `synchronous=FULL`,
  `journal_size_limit=64MiB`. Пул чтения: до 4 соединений `query_only`.
- Каждый метод `store` принимает контекст и ограничен `store.OpTimeout` (3 с);
  SQL без контекста в `store` и `admin` запрещён статическим тестом.
  `kraken backup` получает дедлайн 10 минут.
- `last_seen_at` сессии обновляется условным `UPDATE` не чаще раза в минуту и не
  дольше 250 мс; удалённая параллельным сбросом сессия не воскрешается.
- Обслуживание: `wal_checkpoint(PASSIVE)` каждые 10 минут, `optimize` раз в сутки.

### Миграции

Миграции `src/migrations/NNN.sql` применяются по порядку; DDL, перенос данных и
версия — одной транзакцией, checksum записывается в `schema_migrations`. БД с
чужим checksum `store.Open` не открывает. Отката схемы нет: при откате образа нужна
совместимая схема или восстановление копии. Текущая версия схемы — 8.

## Телеметрия

### Месячные файлы `events-YYYY-MM.db`

- `host(id, name)` — словарь доменов назначения.
- `event` — время, клиент (ID и имя на момент сбора), source IP, хост, порт, метод,
  результат Squid, HTTP-статус, длительность, байты, признак отказа, логин прокси,
  ревизия, способ сопоставления, подключение, `source_id`, `count`, `deny_reason`.
  Индексы: `ts`, `(client_id, ts)`, `(source_ip, ts)` для неописанных, уникальный
  `source_id`.
- `checkpoint` — позиция чтения access.log; пишется в одной транзакции с событиями.

Одинаковые события одной порции в пределах секунды (клиент, источник, хост, порт,
метод, результат, статус, логин, ревизия, подключение, причина отказа) хранятся
одной строкой: `count` — число запросов, `bytes` — сумма, `duration_ms` — максимум.
Все счётчики суммируют `count`. API выдаёт ID события как `<YYYYMM>-<rowid>`.
Путь, query и userinfo URL не хранятся.

Событие пишется в файл месяца, в котором его собрали, поэтому запрос конца месяца,
собранный после полуночи, лежит в следующем файле; чтения по окну учитывают это.

### Агрегаты `rollups.db`

| Таблица | Срок |
| --- | --- |
| `client_15m`, `unknown_15m` | 3 года |
| `client_host_1d`, `unknown_host_1d` | 3 года |
| `client_host_1h`, `unknown_host_1h` | 30 дней |
| `journal_1h` (окна журнала длиннее суток, причины отказов, домены) | 32 дня |
| `watermark`, `journal_watermark` | отметки свёртки по месяцам |

Таблицы `WITHOUT ROWID`, свёртка — UPSERT. Падение между сбором и свёрткой
повторяет её с прежней отметки; потерянный `rollups.db` пересобирается из
месячных файлов. Время корзин — unix-секунды.

### Соединения и повреждения

На файл — одно соединение записи (`_txlock=immediate`, WAL, `synchronous=NORMAL`) и
пул чтения `query_only`; открыто не больше 4 месячных файлов. Файлы создаются с
правами 0600. Битый или несовместимый файл переименовывается в `.broken-<unix>` и
создаётся заново; счётчик — `status.instance.telemetry_broken_files`.

## Сроки хранения

| Данные | Срок |
| --- | --- |
| События | 90 дней (`KRAKEN_EVENTS_RETENTION_DAYS`) и бюджет 5 GiB (`KRAKEN_EVENTS_BUDGET_MB`); удаляются целыми месячными файлами, текущий месяц не удаляется |
| 15-минутные и суточные агрегаты | 3 года, чистка порциями по 5000 строк |
| Почасовые агрегаты | 30 дней (`journal_1h` — 32 дня) |
| Аудит | 3 года без лимита строк (`store.AuditRetention`) |
| Отметки уведомлений | 90 дней |
| Ревизии | Последние 20 и все, на которые ссылается успешная операция |

Чистку управляющей БД выполняет `store.Prune`, телеметрии — `telemetry.Store.Maintain`
в общем периодическом тике. Пороги диска — [observability](../operations/observability.md#хранение-и-место-на-диске).

## Время и идентификаторы

Время в API — UTC RFC 3339; UI показывает московское время. Идентификаторы —
непрозрачные строки; порядок задаёт время, а не ID. Байты и длительности
передаются целыми числами с явными единицами.
