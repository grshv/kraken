# Web-интерфейс

Рабочее имя — Squid Control. Это закрытый инструмент администратора.
Язык первой версии — русский; код, network identifiers и Squid result codes
сохраняют английское написание. Визуальное направление — диспетчерская сети:
доступ, путь запроса, отклонения и действия администратора.

## Основной акцент

Открывающая страница отвечает на три вопроса: работает ли proxy, какие VM имеют
доступ и что сейчас требует действия. Вместо стены одинаковых KPI-карточек —
строка состояния пути VM → proxy → internet, таблица клиентов и лента последних
отказов. Переключатель «Все события / Только отказы» важнее декоративного графика.

## Визуальная система

| Canvas | `#F2F6FA` | Нейтральный светлый фон |
| Surface | `#FFFFFF` | Рабочие таблицы и формы |
| Ink | `#172D45` | Основной текст и навигация |

| Healthy | `#16664C` | Подтверждённое рабочее состояние |
| Warning | `#89520B` | Требуется внимание |
| Danger | `#B42336` | Отказ или опасное действие |

Текст/фон проверяются на контраст в реализации; наличие hex не доказывает WCAG.
Основной шрифт — локально поставляемый IBM Plex Sans с кириллицей, сетевые значения
и diff — IBM Plex Mono; лицензии и файлы шрифтов включить при реализации.
Fallback — системные sans/monospace. Из VM в интернет за шрифтами не обращаться.
Размеры: основной текст 15–16 px, заголовки 22/30 px, код 13–14 px.
Табличные числа с единицами, IP и домены копируются одной кнопкой.

Главный выразительный элемент — схема пути соединения с состоянием каждого участка.
Остальная типографика спокойная, без градиентов и анимационных украшений.
Выравнивание влево; таблицы первичны; цвет всегда дублируется текстом/значком.

видимый focus, подписи полей, reduced-motion и доступные live-status updates.

## Страницы

### Вход

Название инсталляции, имя, пароль, «Войти». Общая ошибка входа без раскрытия
существования username. TLS обязателен. Нет публичной регистрации или default password.
При отсутствии первого admin — понятная инструкция для локального оператора.

### Обзор

Состояния Squid, модуля управления, DNS/проверяемого ресурса; active revision и время проверки.
Видимый баннер «Есть неприменённые изменения». События по умолчанию компактны.
Stale данные не зелёные: «Нет свежей проверки с …». Отказ панели не подписывается
как отказ proxy, если runtime не измерен.

### Клиенты

Таблица name/source IP, enabled, режим доступа, TLS-профиль, последнее событие.
Фильтры «По списку», «Весь web», «Есть отказы». Создание VM через имя, адрес и
политику. Пересекающийся CIDR показывает конфликтующую запись до сохранения;
сервер повторяет проверку. Изменение формы сохраняет draft.

В карточке VM: правила, события, кнопки «Показать настройку APT/curl»,
«Проверить правила», «Отключить доступ». Никакого произвольного удалённого shell.
Настройки клиента — готовый фрагмент с выбранными именами/портами/cert trust,
но без пароля или signing key. Симуляция правила не выдаётся за реальный запрос.

### Политики

«Весь web» либо «Только разрешённые ресурсы». Список доменов с отдельным флагом
поддоменов, описание, привязанные VM. При domain entry не принимать URL-пути.
Подсказка: «Для HTTPS в режиме туннеля доступны правила по домену и порту».
Общие защитные запреты видны, но не отключаются обычной формой.

### События

Время с timezone, VM/IP, destination, HTTP/CONNECT, proxy result, duration,
доступные bytes, TLS mode. Фильтрация на сервере, pagination/cursor, bounded export
только при реализации отдельного защищённого endpoint. URL не исполняется как HTML.

Drawer события разделяет «Наблюдалось в логе» и «Оценка по текущей политике».
Для tunnel явно: «Содержимое HTTPS не расшифровывается». При отсутствии исходного
поля — «Нет данных», а не ноль. Ошибка TLS сопровождается следующим полезным шагом.

### Изменения

Список черновиков/ревизий, автор, время и исход операции. Preview показывает
смысловой diff: затронутые VM, добавленные/удалённые домены, режим TLS;
raw generated config доступен read-only как техническая подробность.

Поток: **Сохранить черновик → Проверить → Применить**. После изменения validation
устаревает. Apply показывает этапы и operation ID; браузер можно закрыть без отмены.
При конфликте — загрузить актуальную версию, не перезаписать молча.
При rollback: «Предыдущая конфигурация восстановлена» только после verification.
Degraded предлагает runbook и блокирует новые apply до recovery.

### Сертификаты

Отдельные блоки: панель, TLS к прокси, CA для inspection. Показывать SAN, issuer,
fingerprint, срок и задействованные VM. Публичную цепочку можно скачать, signing
private key недоступен. В MVP provisioning локальный; кнопки upload private key нет.
Назначение inspect-профиля объясняет trust requirements и bypass, не обещает
«сертификат установлен на VM» без подтверждения клиента.

### Настройки

Read-only deployment pins/capabilities, timezone отображения, локальные admin accounts,
retention и storage health в пределах реализованных операций. Restart, cache purge,
image upgrade и shell не добавляются «заодно».

## Состояния, которые нельзя пропустить

Empty clients → «Добавить VM». Empty allowlist → «Доступ к ресурсам закрыт».
Недоступен модуль управления → режим просмотра, существующий proxy может работать.
Missing TLS capability → профиль недоступен с конкретным объяснением.
Expiry → дата/время и нужное действие. Unknown status → подпись о нехватке данных.
Ошибки сети сохраняют введённую форму. Успешное сохранение не выглядит как apply.

## Проверка дизайна перед кодом

Направление пересмотрено в пользу таблицы VM и пути соединения вместо общего
SaaS-dashboard: они непосредственно отвечают задачам доступа и диагностики.
Красота не требует крупных статистических чисел, hero-баннера или графиков без
рабочего источника данных. Visual QA проводится после реализации на desktop и
узком экране, с длинным доменом, кириллицей, empty/error/degraded и keyboard flow.
