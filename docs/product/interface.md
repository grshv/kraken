# Web-интерфейс

Описывает существующие экраны. Новый интерфейс делается по согласованному прототипу
[prototype/kraken-ui.html](prototype/kraken-ui.html), решения — в [decisions](decisions.md).

Закрытая русскоязычная рабочая панель. Цель — управлять доступом и находить
запросы/отказы, без маркетингового текста и повторения архитектурной документации.

## Компоновка

React/Vite использует готовые компоненты [shadcn/ui](https://ui.shadcn.com/docs/installation/vite)
(New York, Radix), установленные официальным CLI 4.23.0. Исходники компонентов
в `src/web/src/components/ui`, конфигурация CLI — `src/web/components.json`.
Это локальные компоненты в embedded bundle: runtime CDN и Node server не нужны.
Tailwind CSS 4 задаёт utility styles; семантические цвета и радиусы — `theme.css`,
компоновка приложения — `style.css`. Собственные глобальные button/input styles
не подменяют состояния готовых компонентов.

Sidebar с группами «Прокси», «Управление», «Доступ» и активным разделом. На малых
экранах — Sheet, закрывающийся после выбора раздела. Формы используют Input,
Textarea, Select; таблицы — Table, действия — Button, состояния — Badge,
обзор — Card. Dialog управляет фокусом, Escape и блокировкой фоновой прокрутки;
Tabs обеспечивают клавиатурный переход между настройками. Одна основная кнопка
действия, технические объяснения раскрываются по необходимости. Нет декоративной
схемы сети и неподтверждённых графиков. Контекстные предупреждения сохраняются.

Направление компоновки проверено с публичным [UI/UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill):
компактная административная панель, иерархия, читаемые таблицы, контраст и клавиатура.
Скилл установлен в личном окружении разработки, не добавлен как runtime dependency
и не скопирован в агентские документы проекта. Выбор компоновки — решение проекта;
общие рекомендации скилла не являются гарантией доступности.

Canvas #F8FAFC, Surface #FFFFFF, Ink #0F172A, Action #2563EB. Локальные Inter с
кириллицей, Lucide icons, лицензии в `public/licenses`. Внешнего
font CDN нет. Текст дополняет цвет, кнопки с одной иконкой имеют accessible names.
Поддерживаются reduced motion, skip link, видимый keyboard focus и мобильное меню.
Есть полные светлая/тёмная схемы. Начальная тема — светлая независимо от ОС;
тёмная включается только явным выбором, который затем сохраняется. Переключение — одной кнопкой с солнцем/луной рядом с выходом.
В sidebar только «Панель управления» шрифтом меню, без логотипа/бренда/аватара.
Desktop trigger находится внутри sidebar и доступен после сворачивания; на mobile
кнопка открытия отделена от скрытого меню. Источники проверены 27.10.2026.

## Роли и разделы

Выбраны владельцем admin и manager. Admin видит все разделы. Manager видит
свою область (клиенты, разделяемые политики, свои логины прокси), журналы
и аудит по области. Сервер возвращает 403 admin_required на недоступных
endpoint'ах и 404 на объекты вне области. Роль и permissions приходят в
session response, не берутся из localStorage.

Обзор отвечает на три рабочих вопроса: подтверждено ли состояние прокси и
применения; кто использовал доступ недавно; где наблюдались отказы и ошибки.
Карточка «Состояние прокси» имеет собственный заголовок и статус. Внутри —
Squid version/uptime/активные запросы. Под ними — режим
и количество включённых клиентов из confirmed runtime snapshot, не draft;
нет включённых клиентов явно означает закрытый доступ в structured mode.
Переход «Правила доступа» доступен администратору и ничего не изменяет.

Основное место занимают две таблицы за выбранный период: 15 минут, час, день, неделя или последние30 дней:
сгруппированные повторные проблемы и обращения источников. Группы проблем
объединяют IP, proxy username, destination и точный Squid result; показаны количество
и последнее время. Активность источника: обращения/отказы/ошибки ответа/байты и
last_seen. Это наблюдения завершённых обращений, не online/offline health клиента.
DENIED — отказ прокси, остальные >=400/FAIL/ABORTED — отдельные ошибки;
access.log не доказывает точное сработавшее ACL. Действие строки открывает журнал
с IP/destination/result/временем уже выбранного периода. Открытые CONNECT видны
в live active count, в истории появляются после закрытия.

Нет суточного графика, больших счётчиков и списка повторяющихся ошибок без
группировки. CPU/peak memory/cache/rates доступны под «Технические показатели».
Неизмеренные значения — «—»; stale/error/gap не скрываются. Live sampling — 5с,
activity — 15с; не выдавать cache-manager polling за пользовательский трафик.
Показаны максимум10 источников/групп с явным указанием большего итога. CRUD в
обзоре нет, он не применяет draft и не редактирует конфигурацию.

Клиенты: host/network/group, IP/CIDR, режим all_web/allowlist, домены/поддомены,
transport и необязательный proxy login. Таблица показывает сами разрешённые
домены и признак поддоменов; первые пять видны сразу, остаток раскрывается в строке.
Счётчик без списка не заменяет правила. Пересекающиеся источники допускаются
только для разных auth usernames. Выбор логина требует TLS, при отсутствии cert
контрол объясняет недоступность; смена transport не удаляет auth binding молча.

## Настройки и применение

Вкладки сети/ACL, кеша, DNS/timeouts и squid.conf. Порты подключения внутри контейнера — параметры установки, из форм удалены;
смена через draft или старую revision отклоняется API. Порты назначения/CONNECT
сохраняются как действительные ACL-настройки. Политика — сначала draft, затем read-only preview/parse/apply/fingerprint;
отдельная история и проверяемый rollback. Открытие «Изменений» не создаёт revision.
No-op не предлагает применение. Одинаковые defaults и эквивалентные CIDR не
выдаются за правку; обновление managed config отмечается отдельно и раскрывает
построчный diff сразу. Revision создаётся для validate, результат связан
именно с ней. Потеря связи после получения operation ID возобновляет только GET
опрос, не повторяет mutation. Несохранённые настройки защищены при уходе из раздела.
Expert section заменяет visual user ACL, не служебные paths/listeners/sc_ guard.
При переходе в expert с пустым редактором подгружается непустой шаблон;
пустой набор клиентов даёт `http_access deny all`, не пустой экран. Итоговый полный
squid.conf сохранённого черновика читается здесь же через preview, отдельно от
редактируемого блока. Локальные изменения требуют сохранения для обновления preview.
Включённые auth clients не совмещаются с expert mode. Запреты helpers/includes/
executables сохраняются; только compiler владеет фиксированными auth helpers.

## История и аудит

События: компактная сетка фильтров клиента, точного IP, части назначения,
метода, точного результата Squid и локального диапазона времени. Сервер применяет
все фильтры до пагинации; from включительно, to исключительно, часовой пояс
передаётся явно. Сброс возвращает последние записи без фильтров. Есть размер
страницы 25/50/100/200, «Новее»/«Раньше», пауза и «Последние записи».
Live page обновляется каждые 10 секунд; на старых страницах опрос приостановлен.
Источник подписывается по IP и, для auth clients, logged proxy username при сборе,
не как доказанная историческая ACL/revision. Для HTTPS доступны только CONNECT
metadata. TTL событий 30 дней по сбору/50 000 строк, audit 90 дней/5000 строк.

Freshness, source missing/backlog/gap и error не замалчиваются. При API error
старые строки сохраняются с предупреждением. Общего блока «О журнале» в рабочем экране нет; ограничения описаны в документации,
актуальные ошибки/freshness остаются рядом с данными. Audit показывает
участника/действие/объект/время, actor/action filters и страницы. Итог apply проверяют
в operation/history, не по факту наличия audit action.

## Учётные записи

Пользователи: создать admin/manager, сменить роль/пароль, блокировать/разблокировать.
Секретный ввод — password field, очищается после операции/закрытия/ошибки. Старый
пароль/hash не показываются. Last-admin guard проверяется backend; собственная
role/password mutation отзывает сессию и требует входа заново.

Логины прокси: отдельный список, создание/смена пароля и блокировка. Логин затем
назначается клиенту. Это не пользователь панели. Успешная аутентификация не
отменяет source/destination policy. Open CONNECT может жить до закрытия; новая
блокировка не обозначается как принудительный разрыв всего трафика.

## Справка

Статьи справки — Markdown-файлы в `src/internal/help/articles/*.md`, встроенные
в бинарник через `//go:embed`. У каждой статьи front matter из четырёх полей:
`slug` (равен имени файла без расширения), `title`, `section` и `order`.
Разделы фиксированы кодом: «Начало работы», «Подключение машин», «Сценарии»,
«Как это работает»; индекс сортируется по порядку разделов, затем по `order`.
Ссылки между статьями — `[текст](help:<slug>)`; `make docs-check` проверяет, что
front matter полный, slug уникален и совпадает с файлом, а все `help:` ссылки
разрешаются. API: `GET /api/v1/help` (индекс) и `GET /api/v1/help/{slug}`
(статья), обе требуют `read`. Экран справки в UI — отдельный срез.

## Проверки

Browser fixture — отдельный container/volume и случайные пароли только в памяти.
Проверяются login/expiry, clients/settings/expert, diff/apply/rollback, history,
filters/audit, viewer/API403, block/session revoke и proxy account UI. Desktop и
mobile screenshots проверяются на настоящем приложении; synthetic mock images
не служат доказательством готовности. [ADR 0012](../adr/0012-local-users-and-proxy-passwords.md).

## Единые потоки и владельцы состояния

AppFrame владеет навигационной оболочкой, ThemeProvider — предпочтением темы;
в обоих нет конфигурационных mutations. OverviewPanel только отображает данные,
useOverview опрашивает status/squid metrics/activity с независимым восстановлением
данных и без перекрывающихся фоновых опросов. api.ts отделяет сетевой отказ и
таймаут от HTTP/API error. Network banner снимается успешной проверкой связи,
не является ошибкой Squid и не сохраняется как ошибка последней команды.

SettingsPanel держит локальные dirty поля до сохранения. ChangesPanel показывает
preview/history/operation и вызывает типизированные действия координатора App.
App владеет session/permissions, draft version и связью validation→revision;
useOperationRecovery продолжает чтение известной операции после потери связи.
DiagnosticsPanel владеет фильтрами/cursor и состоянием своего источника.
EntityDialog — единственная оболочка редакторов клиентов, users и proxy accounts:
одинаковые title/body/footer, focus return, cancel/Escape, disabled/pending/error.
Нет сочетания inline account editor с modal client editor. No-op account submit
заблокирован; пустая форма не отзывает сессию. Account изменения действуют сразу,
клиент/настройки — после отдельного применения черновика.

## Геометрия форм

Одинаковый control row не зависит от высоты description. Label grid использует
align-content:start, родительские двухколоночные grids — align-items:start.
Верхние границы paired controls совпадают даже при многострочной подсказке.
Checkbox фильтра занимает высоту control, а не всей группы label+control.
Desktop sidebar header/footer совпадают с gutters заголовков групп; переносы
и mobile layout не меняют порядок label/control/description. Это проверяется
реальными DOM coordinates в браузере, не только отсутствием horizontal overflow.

## Изменения и подтверждение

Изменения показывают сравнение действующей конфигурации с сохранённым черновиком
или явно подписанной исторической ревизией. Настоящий line diff сохраняет общие
строки, даёт три строки контекста и заголовки hunks; автоматически меняющийся
fingerprint нормализуется только в сравнении. Compiler и реальные directives
не скрываются. Полный итоговый конфиг доступен отдельно без нормализации.
«Проверить» создаёт и проверяет immutable revision. После успешной проверки
«Применить» открывает единый Dialog с составом изменений и окончательным
подтверждением; отмена не посылает apply. Откат подтверждается аналогично.
Просмотр несовместимой или текущей исторической ревизии не открывает изменение.

## Единые компоненты и типографика

Все рабочие контролы используют shadcn/ui: Select (Radix с portal), Checkbox,
Button, Input/Textarea, Label, Tabs, Dialog, Sheet/Sidebar, Table, Alert, Card и
Collapsible. SelectField/Panel/Disclosure только собирают эти primitives единообразно.
Нет системных видимых select, нативных checkbox и details. Portal-меню не обрезается
карточками, поддерживает keyboard/Escape/focus и disabled.
Одна гарнитура Inter, два размера: 14px основной текст, меню, подписи, контролы и заголовки секций;
16px заголовки страницы и карточек. Вложенные подписи остаются14px и выделяются весом. Нет monospace даже для
IP, результатов и конфигурации. Размеры заданы общими tokens, включая shadcn
text utilities; иерархия дополнительно выражается весом и цветом, не новыми кеглями.
Collapsed sidebar trigger и menu icons имеют одну горизонтальную ось.

Select/Checkbox/Collapsible/Label/Alert взяты из официального new-york registry
shadcn/ui, с уже установленным единым `radix-ui` и проектным helper `cn`.
Источники проверены28.10.2026: [Select](https://ui.shadcn.com/docs/components/radix/select),
[Radix Select](https://www.radix-ui.com/primitives/docs/components/select).
За день/неделю/месяц last_seen содержит дату и время; периоды скользящие,
«месяц» означает последние30суток, не календарный месяц.

У каждой карточки обзора есть собственный CardHeader/CardTitle: «Состояние прокси»
и «Диагностика доступа». Версия/status/uptime не заменяют заголовок карточки.
«Применённые правила», «Отказы и ошибки» и «Кто использует прокси» — вложенные
подписи14px; они не конкурируют с заголовком16px внешнего блока.
