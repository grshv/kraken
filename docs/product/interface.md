# Интерфейс

Закрытая русскоязычная рабочая панель: управлять доступом клиентов и находить
запросы и отказы. Плотная админка без маркетингового текста. Решения владельца —
в [decisions](decisions.md#интерфейс).

## Визуальная система

- Тема — ахроматические поверхности и один синий акцент для основных действий,
  выбора, фокуса и активного раздела. Статусы: зелёный — успех, красный — отказы,
  янтарный — предупреждения и черновик. Светлая и тёмная темы используют одни
  смысловые роли; начальная — светлая, тёмная включается в меню профиля и
  запоминается.
- Шрифт — IBM Plex Sans (`@fontsource/ibm-plex-sans`, без CDN) с табличными цифрами
  для текста, IP и доменов, без моноширинного. Размеры — 13, 14 и 20 px.
- Поверхности: навигация, рабочая область и всплывающие панели различаются фоном;
  тени только у наложений. Вложенные поля и группы переключателей темнее карточки,
  выбранный элемент светлее группы.
- Метки сущностей — цветное слово или иконка, не плашки. Серым — только
  второстепенное.
- Таблицы — общий прямоугольный контейнер прокрутки, первая и последняя колонки с
  отступом 16 px. Таблица в карточке стоит на её поверхности без своей рамки и
  заливки. Статусы строк не повторяют выбранный фильтр. Длинные значения
  сокращаются с полным текстом в подсказке.
- Пояснения, полный перечень прав, ограничения входа и срок сессии раскрываются по
  запросу (`Disclosure`) — кнопкой на ширину строки высотой от 32 px. Шапки разделов
  не дублируют их назначение.
- Время — московское (МСК); точное значение с датой — в подсказке (`Timestamp`).
  Ревизия везде — `r-<N>` (`revisionLabel`), UUID — только в деталях.
- Иконки — Lucide 16 px. Favicon — кракен, светлый или тёмный по
  `prefers-color-scheme`.
- Поддерживаются reduced motion, skip link и видимый фокус клавиатуры. Минимальная
  ширина окна — 1024 px без горизонтальной прокрутки страницы.

## Каркас

- **Колонка разделов** 64 px на всю высоту: знак-кракен сверху, кнопки разделов
  (`navItems(role)`), профиль снизу. Разделы: Клиенты, Политики, Журнал, Аудит,
  Аккаунты; внизу Справка и (администратору) Настройки. Выбранная кнопка — на синей
  подложке. Точка у «Клиентов» — новые уведомления в доступной области, число — в
  подсказке.
- **Шапка рабочей области** 64 px: путь «Kraken / раздел», компактный «Поиск ⌘K» и
  индикатор состояния — цветная точка и обычный текст. Popover индикатора
  (загружается при открытии из `/status` и `/squid/metrics`): «Squid работает / не
  отвечает» с давностью проверки, экземпляр, ревизия и время применения, версия и
  аптайм Squid, порты, сбор журнала, место на томе; ссылки «История применений» и
  (администратору) «Настройки экземпляра».
- **Панели раздела** — только общие обёртки `components/kraken/layout.tsx`:
  `ListPane` слева (в Журнале — фильтры), `InspectorPane` в центре, `DetailPane`
  справа. Все — shadcn Resizable в группе `kraken-main`: список 220–440 px (начально
  260), деталь 280–520 px, центр не уже 500 px; ширина запоминается, разделитель
  доступен с клавиатуры. Фильтр списка — кнопка со значком рядом с поиском, варианты
  и счётчики в меню.
- **Полоса над панелями** (`banner`) — ошибки связи и API, недоступный Squid (с
  пояснением, что Kraken перезапускает его с последней рабочей ревизией).
- **Плашка черновика** внизу — пока `/status.has_unapplied_changes` истинно: янтарная
  метка «Черновик конфигурации», счётчик изменённых объектов, пояснение, что трафик
  ещё не изменился, «Сбросить» (с подтверждением) и «Проверить и применить».
- **Меню профиля**: имя, роль, «Мой аккаунт», «Сменить пароль», «Завершить другие
  сессии», тема, выход. «Сменить пароль» — диалог с текущим паролем и новым дважды
  (`PUT /session/password`); правила (12–1024 байт, не совпадает с текущим)
  проверяются и в форме; эта сессия остаётся, другие завершаются. Поле пароля теряет
  фокус до смены экрана (иначе Chrome на macOS оставляет Secure Input).

## Командная палитра

⌘K / Ctrl+K открывает окно до 760 px (по высоте — в пределах экрана) со строкой
ввода 64 px и крестиком по центру; результаты прокручиваются внутри окна. Фильтр по
подстроке, стрелки, Enter, Escape. Группы: «Действия», «Клиенты» (по имени и сетям),
после ввода текста — «Домены» (из журнала за 24 ч с клиентами, из политик, своих
доменов и запретов; выбор открывает Журнал на виде «Домены») и «Запретить для всех»
(администратору), затем «Политики» и «Разделы». Действия: «Новый клиент», «Новый
логин прокси», «Запретить домен для всех» (администратору), «Проверить и применить
черновик». Доступность действия решает `paletteIntent(id, role)`; недоступное не
показывается.

## Клиенты

**Список**: поиск по имени, IP и домену; фильтр — все / с отказами за 24 ч /
изменены в черновике; sparkline по часам; метки «новый / изменён / удалён»
(`entityMarks`). Группа «Неописанные источники» (`/inspector/unknown-sources`) —
адреса, не покрытые клиентами действующей конфигурации, с назначениями и давностью;
игнорируемые скрыты до «Показать игнорируемые (N)», просмотренные приглушены.

**Шапка клиента** — одна строка: имя, последняя активность, описание и IP рядом с
действиями; дублирование и выключение — в меню «Ещё».

**Вкладки**:

- **Обзор.** Новые отказанные домены за 7 дней (нет в итоговом списке) с
  «Разобрать» (во «Доступ») и «Отметить просмотренными». Активность: метрики 2×2
  (запросы, отказы, трафик за 24 ч, соединения «сейчас») и график трафика за 24 ч по
  15 минутам. Назначения за 24 ч — основной рабочий список с колонками запросов и
  отказов, красным только счётчик отказов, «Разрешить» — синее действие. Справа —
  правила (итоговый список метками, политики, свои домены, запреты поверх,
  подключение) и последние запросы строками «время / назначение / результат».
  Колонки 1,65:1, правая не уже 280 px; на узком инспекторе блоки идут друг за другом.
- **Доступ.** Режим (список доменов / весь веб / нет доступа) — компактная строка с
  раскрываемым выбором; при «весь веб» списки скрыты, но сохраняются. Таблица
  «Отказанные домены» (`/notifications?client_id=`): фильтр Новые / Просмотренные /
  Игнор / Все, поиск, выбор на странице, по 50 строк; у строки «Разрешить» и меню
  (Просмотрено, Игнорировать, В новые, Запретить для всех); после выбора — те же
  действия пачкой. Уже добавленный в черновик домен помечен «в черновике». Карточки:
  «Политики» (подключённые с числом доменов и других клиентов, «Подключить…»,
  отключение), «Свои домены» (редактор с запросами клиента за 24 ч и меткой «не
  используется», переключатель «с поддоменами» включён по умолчанию, `*.x` всегда с
  поддоменами; «Сделать политикой…» переносит домены в новую политику), «Итоговый
  список» с источником каждой строки («свой» и/или имена политик).
- **Источник и подключение.** Имя, описание, тип, включён; адреса по строке с
  размером сети, проверка пересечений и, для менеджера, вхождения в его сети.
  Подключение — HTTP или TLS с логином прокси. TLS недоступен с пояснением и
  ссылкой на справку, если нет сертификата прокси или логинов (`tlsUnavailable`).
- **Запросы.** Тот же компонент, что раздел Журнал, суженный до клиента, с
  «Открыть в журнале».
- **История.** Изменения клиента по парам применённых ревизий и черновику:
  режим, подключение, политики, итоговый список; автор — из аудита.

**Создание** — форма в три шага рядом со списком, в том числе из неописанного
источника: кто (имя, тип, адреса), куда (политики и свои домены, весь веб или пока
без доступа), подключение (HTTP или TLS с логином). Для источника — «Просмотрено»,
«Игнорировать», «Снять отметку». Удаление — с подтверждением.

Готовых наборов доменов («Ubuntu / Debian», «Python») нет: домены задаются явно.

## Политики

Администратору первая строка списка — «Запрещено для всех» (`settings.blocked_domains`).
Далее именованные наборы доменов: число подключивших клиентов («не подключена»),
доменов и запросов за 24 ч; метка черновика — во второй строке рядом с числом
доменов. Деталь: тот же редактор доменов (метка «не используется» — ноль запросов
за 7 дней), попадания за 24 ч и 7 дней, «Чего не хватает» (отказанные домены
клиентов политики со списком, «Добавить» кладёт домен в эту политику), клиенты
политики. Создать, дублировать, переименовать на месте, удалить — только если ни
один клиент её не подключил. Менеджер не меняет политику с чужими клиентами:
кнопки неактивны с пояснением.

## Журнал

Тот же компонент — раздел и вкладка «Запросы» клиента (`log/Journal.tsx`).

- **Виды**: «Запросы» и «Домены» (запросы по домену: всего, разрешено, отказов,
  источников, объём, последний).
- **Период**: 1 ч / 24 ч (по умолчанию) / 7 дн / 30 дн или календарь по МСК, не
  длиннее 31 суток; окна длиннее суток выравниваются по часу. Окно листается
  стрелками ‹ › на свою длину, «Сейчас» возвращает живой период, выделение на
  графике приближает время.
- **Фильтры** слева: результат (все / отказы / разрешено), клиенты с поиском
  (включая «Не описан»), причины отказа и методы — отметками, «любой из». Счётчики
  групп — из `/events/facets`. Поиск «Домен или IP»: адрес — `source_ip`, иначе
  подстрока `destination`. Состояние — в адресе (`#log=…`).
- **Строка над таблицей** — 40 px при любых фильтрах: счётчик, метки активных
  фильтров с горизонтальной прокруткой, листание и компактный период; полный период
  с МСК — в подсказке.
- **Сводка** (сворачивается): запросы, отказы, объём, неописанные источники,
  график разрешённых и отказанных, топ-5 доменов и клиентов; каждая цифра сужает
  журнал.
- **Таблица запросов**: время, источник (клиент и IP), назначение, метод, объём,
  результат с причиной отказа красным и `×N` для схлопнутых записей. Причина отказа
  важнее HTTP-кода. «Показать ещё» по курсору; признаки разрыва и отставания сбора
  — «сбор журнала отстаёт». Автообновление 5 с с «Пауза».
- **Клавиши**: j/k — строки, a — разрешить домен клиенту, Esc — закрыть деталь.
- **Деталь запроса**: результат, источник, назначение; для отказа — причина одной
  фразой (`whyText`) со ссылкой на справку; «Разрешить» — только клиенту или в
  политику с перечнем затронутых клиентов; «Описать IP как клиента»; «Запретить
  для всех» (администратору, кроме защитных отказов); свёрнутые технические данные.
- **Деталь домена**: счётчики, порты, источники (до 20), «Показать запросы»,
  «Разрешить» для клиентов с отказом и «Запретить для всех».

## Аудит

Действия по дням; фильтр-категория (все / применения / входы / учётки) и поиск по
пользователю; подгрузка по курсору. Заголовок строки — суть изменения из `detail`,
под ним действие и автор. Названия действий и категории — `audit/actions` (у
каждого действия сервера есть русское название). Деталь: кто, когда, объект; у
ревизии и изменений черновика — «Что изменилось» тем же списком +/−/~, что в
панели проверки.

## Аккаунты

Две группы: «Панель управления» (`/users`, только администратору) и «Логины прокси»
(`/proxy-accounts`, по области). Менеджер видит только логины.

- **Пользователь панели**: роль (два варианта и права текущей роли), «Входы»
  (последний вход, неудачные за 24 ч, пороги), «Последние действия» (5 строк и «Весь
  аудит»), «Сессии» таблицей (устройство по User-Agent, адрес, начало, активность;
  «Завершить», «Завершить другие»). Для менеджера — область: сети и клиенты
  (`/users/{username}/scope`), без технических ID. Блокировка в списке —
  приглушённый значок с подсказкой и доступным именем, в карточке — красный статус.
  Последнего администратора нельзя понизить или заблокировать: кнопка неактивна,
  сервер тоже отказывает.
- **Логин прокси**: где используется, владелец, показатели за 24 ч (запросы,
  неверный пароль, отказы, адреса) и «С каких адресов» с подсказкой, если с адреса
  идут неверные пароли.
- Пароль показывается только при вводе и не сохраняется в форме после отправки.
- Изменения аккаунтов действуют сразу, без черновика; это видно до действия.

## Настройки

Только администратору. Слева разделы, справа деталь. Правки идут в черновик
(«В черновик»), изменённое поле помечено «в черновике».

- «Встроенная защита» — описание защитных запретов и `allow_private_destinations`.
- «Вышестоящий прокси» — `upstream_proxy`: IP, порт, `exclusive`.
- «Приватность» — `hide_client_address`.
- «Экземпляр и порты» — имя экземпляра (только чтение), разрешённые порты и порты
  `CONNECT`, порты прокси (только чтение).
- «Сертификаты TLS» — кому выдан, имена, издатель, срок; предупреждение за 30 дней.
- «DNS», «Таймауты и лимиты», «Кеш», «Журналы».
- «squid.conf вручную» — предупреждение об аварийном режиме, редактор
  `expert_config`, «Вставить шаблон»; ошибки сервера — у редактора.

## Справка

Оглавление `GET /help` и статья `GET /help/{slug}`: первый абзац — подзаголовок,
при нескольких разделах — «Содержание». Markdown рендерится без сырого HTML. Ссылки
`help:<slug>` открываются внутри раздела, внешние — в новой вкладке с
`rel="noreferrer noopener"`. Статья с `screen` показывает кнопку «Открыть «Раздел»»,
если раздел виден роли.

## Черновик и применение

Все правки клиентов, политик и настроек идут в черновик (`PUT /configuration/draft`
с `expected_version`). Конфликт версии — тост и перечитывание черновика; коды
`source_outside_scope`, `source_overlap`, `policy_shared_out_of_scope`,
`username_taken` показываются у поля.

**Панель проверки** — sheet справа до 620 px:

- заголовок с действующей ревизией `r-<N>`;
- изменения по объектам из свежего предпросмотра (клиент, каждая политика,
  настройки Squid, режим и expert-секция, TLS-профили) с маркером +/−/~ и деталями
  (поля, добавленное и удалённое); у каждой строки, кроме TLS-профилей, «Отменить»
  возвращает объект к действующей ревизии (`revertChange`, правила — в
  [decisions](decisions.md#интерфейс));
- «Влияние на трафик» (`/inspector/draft-impact`): клиенты, чьи разрешённые за 24 ч
  запросы начнут получать отказ, число исчезающих отказов, напоминание, что открытые
  туннели не рвутся;
- свёрнутые «Изменённые фрагменты squid.conf» (администратору);
- у менеджера с чужими изменениями — причина запрета применения до нажатия.

**Применение**: `POST /revisions` → (администратору) `GET /revisions/{id}/preview`
→ `POST /operations` validate, затем apply → опрос `GET /operations/{id}`. Ключ
идемпотентности — случайный UUID. Состояния `applyFlow`: idle, running (с шагом),
done, failed (с кодом), conflict, rolled_back. После успеха список остаётся с
заголовком «Применено в r-N» и «Открыть в аудите». `rolled_back` — Squid вернулся к
прежней ревизии, трафик не прерван. Текст ошибки Squid не показывается. При потере
связи после получения ID операции опрос возобновляется (`useOperationRecovery`),
запрос не повторяется.

## Роли

Администратор видит все разделы. Менеджер — свою область (клиенты, политики,
журнал, аудит, свои логины прокси) и Справку; Настройки ему недоступны. Роль и
`permissions` приходят в ответе сессии. Сервер фильтрует списки и запрещает
правку вне области ([ADR 0007](../adr/0007-admin-and-manager-roles.md)); UI лишь
прячет недоступное.

## Вход

Карточка со знаком, форма входа по Enter, индикатор связи, серверные ошибки.
При 401 UI получает новый CSRF holder через `/session` и показывает вход без
перезагрузки.

## Реализация

- React, Vite, TypeScript; компоненты [shadcn/ui](https://ui.shadcn.com/docs/installation/vite)
  (New York, Radix) в `src/web/src/components/ui`, обёртки Kraken — в
  `src/web/src/components/kraken`; Tailwind CSS 4. Бандл встраивается в бинарник,
  CDN и Node в runtime нет; лицензии шрифтов — `public/licenses`.
- Токены цветов, статусов и шкала текста — `theme.css`; `style.css` держит только
  сбросы и skip link. У компонентов shadcn меняются только классы и варианты.
- CSP запрещает произвольные inline-стили. Встроенные `<style>` компонентов
  (sonner, Radix ScrollArea, цвета графиков) пропускаются по хешам, которые
  `npm run build` считает в `dist/csp-style-hashes.json`; стиль блокировки
  прокрутки диалогов — по nonce страницы.
- `api.ts` отделяет сетевой отказ и таймаут от ошибки API; код ошибки
  (`ApiError.code`) передаётся дальше без разбора строк.
- Логика экранов — в чистых модулях с vitest ([testing](../development/testing.md#web-unit-тесты)).
