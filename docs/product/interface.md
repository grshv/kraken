# Web-интерфейс

Описывает текущее устройство каркаса панели. Вид и поведение — по
согласованному прототипу [prototype/kraken-ui.html](prototype/kraken-ui.html);
решения — в [decisions](decisions.md).

Закрытая русскоязычная рабочая панель. Цель — управлять доступом клиентов и
находить запросы/отказы, без маркетингового текста и повторения архитектурной
документации.

## Компоновка

React/Vite использует готовые компоненты [shadcn/ui](https://ui.shadcn.com/docs/installation/vite)
(New York, Radix). Исходники компонентов в `src/web/src/components/ui`,
конфигурация CLI — `src/web/components.json`. Локальные компоненты в embedded
bundle: runtime CDN и Node server не нужны. Tailwind CSS 4 задаёт utility
styles; семантические цвета и радиусы — `theme.css`, компоновка оболочки —
`style.css`. Собственные глобальные button/input styles не подменяют состояния
готовых компонентов.

Каркас «инспектор»: шапка по колонкам, левая колонка-разделов (rail), область
список + деталь с перетаскиваемыми разделителями, нижняя панель черновика и
панель проверки справа. Все правки идут в черновик; применение — отдельная
операция. На малых экранах шапка сжимается, поиск и индикатор состояния
остаются.

Нейтральная тема shadcn (графит), светлая и тёмная. Шрифты — Geist и Geist
Mono (npm-пакеты `@fontsource/geist`, `@fontsource/geist-mono`), Inter
удалён. Единая шкала текста: 11/12/13/14/20 px. Geist Mono — только для
машинных значений (IP, домены, конфигурация, ревизии). Lucide icons. Внешнего
font CDN нет; лицензии в `public/licenses`. Поддерживаются reduced motion,
skip link, видимый keyboard focus. Начальная тема — светлая независимо от ОС;
тёмная включается явным выбором и сохраняется. Переключатель темы — в левой
колонке под разделами. Favicon — собственный кракен (`public/kraken-mark.svg`),
светлый или тёмный по `prefers-color-scheme`.

## Шапка

Колонки: логотип-кракен над колонкой разделов, надпись KRAKEN заглавными с
разрядкой, поиск ⌘K по центру, индикатор состояния справа. Логотип —
геометрический кракен без плашки, `currentColor` наследует цвет темы. Поиск
открывает командную палитру; индикатор состояния — popover с полями из
`/status`: работает ли Squid, имя экземпляра, применённая ревизия, свежесть
журнала. Поле показывается, если есть в ответе, иначе прочерк. При недоступном
Squid под шапкой — баннер с пояснением, что Kraken перезапускает его с последней
рабочей ревизией.

## Левая колонка и профиль

Разделы из `navItems(role)`: main — Клиенты, Политики, Журнал, Аудит, Аккаунты;
bottom — Справка и (только admin) Настройки. Менеджер не видит Настройки.
Под разделами — переключатель темы и аватар с меню профиля (имя, роль, выход).
Меню закрывается по Outside click, Escape и выбору действия. Сменить пароль и
«Мой аккаунт» открывают раздел Аккаунты.

## Панели переменной ширины

Список и деталь — панели с перетаскиванием. Пределы из `PANE_LIMITS`:
список 220–440 px, деталь 280–520 px. Ширина запоминается в `localStorage`
(в `try/catch`), NaN и некорректные значения сводятся к минимуму. Двойной клик
по разделителю сбрасывает ширину к середине диапазона; стрелки сдвигают на
16 px. Разделитель доступен с клавиатуры (`role="separator"`).

## Командная палитра

⌘K / Ctrl+K: переход по разделам и действия-заглушки (новый клиент, запретить
домен для всех, проверить и применить, новый логин прокси). Фильтрация по
подстроке, навигация стрелками, Enter выполняет, Escape закрывает. Действия,
которые требуют экранов следующего среза, показывают тост «появится в
следующем срезе».

## Черновик и применение

Нижняя панель черновика видна, когда `/status.has_unapplied_changes` истинно:
счётчик изменений, «Сбросить черновик» (с подтверждением) и «Проверить и
применить». Когда изменений нет — бейдж «Черновик пуст» и ссылка на историю
применений. Панель проверки (sheet справа, до 620 px) показывает состав
изменений и шаги revision → validate → apply по реальному API:

- `POST /revisions` с `expected_draft_version`;
- для admin — `GET /revisions/{id}/preview` за `expected_applied_revision`;
  менеджеру preview недоступен (`403 admin_required`), тогда `expected`
  берётся из ответа `POST /revisions`, если поле есть, иначе `null`;
- `POST /operations` (`validate`, затем `apply` с `validation_operation_id`);
- опрос `GET /operations/{id}` до терминального статуса;
- `Idempotency-Key` — случайный (UUID, fallback на случайную строку 16+ символов).

Состояния `applyFlow`: idle, running (с шагом), done, failed (с кодом),
conflict, rolled_back. Конфликт (`409`) показывает кнопку «Обновить черновик».
`draft_out_of_scope` (403) — понятный текст: в черновике есть изменения вне
области менеджера, применить целиком может только администратор. Откат
(`rolled_back`) — Squid вернулся к прежней ревизии, трафик не прерван.
При ошибке Squid (rejected) текст ошибки не показывается, в нём могут быть
секреты. При потере связи после получения operation ID опрос возобновляется
через `useOperationRecovery`, мутация не повторяется.

## Разделы

Клиенты. Список с поиском (имя, IP, домен), фильтрами (все / с отказами /
в черновике), sparkline и метками «новый/изменён/удалён» по `entityMarks(active,
draft)`; отдельная группа «Неописанные источники» из `/inspector/unknown-sources`
с переходом в форму создания. Инспектор на пять вкладок: Обзор (callout об
отказах с кнопкой «Разрешить», KPI и топ назначений из
`/inspector/clients/{id}/stats`, карточка правил), Доступ (своя / общая /
весь веб / нет доступа; редактор доменов `parseDomainInput`/`mergeDestinations`;
шаблоны из `/inspector/domain-templates`; предупреждение об общих клиентах),
Источник и подключение (имя, описание, тип, включён; адреса через `parseNetwork`
с проверкой пересечения `networksOverlap` и, для менеджера, вхождением в его
сети через `networkWithin`; логин прокси из `/proxy-accounts`), Запросы (события
из `/events?client_id=` и переход в Журнал), История (`/audit?entity_id=`).
Создание клиента — форма и создание из неописанного IP; дублировать, отключить,
удалить с подтверждением.

Политики. Список именованных списков доменов с числом клиентов и доменов,
деталь с режимом (список доменов / весь веб), тем же редактором доменов,
попаданиями 24 ч / 7 дней из `/inspector/policies/{id}/hits` и списком клиентов
политики. Создать, переименовать, удалить (только если нет клиентов; менеджер
не меняет общую политику с чужими клиентами — кнопка неактивна с пояснением).

Все правки клиентов и политик идут в черновик через `PUT /configuration/draft`
с `expected_version`; `409 revision_conflict` → тост и перечитывание черновика
и действующей конфигурации; коды `source_outside_scope`, `source_overlap`,
`policy_shared_out_of_scope`, `username_taken` показываются у поля по
`ApiError.code`. Кнопка «Сбросить черновик» в нижней панели вызывает
`DELETE /configuration/draft` (с подтверждением). Действующая конфигурация для
сравнения меток приходит из `GET /configuration/active`; менеджер видит свою
область, действия вне области недоступны. Пустые состояния (нет клиентов, нет
политик) показывают создание первого объекта, в том числе из неописанного
источника.

Журнал. Поток событий прокси с поиском по токенам (`client:`, `host:`,
`method:`, `ip:`/`source:`, `result:`/`результат:` со значениями
`allowed|разрешено|denied|отказ`; всё прочее — свободный текст). Поиск
переходит в параметры `GET /events`: `client` разрешается в `client_id` по
имени клиента из черновика/активного снимка, `result:denied` →
`failures_only=true`, `host` и свободный текст — в `destination`, `method` и
`ip` — одноимённые параметры. Последние 200 событий, подгрузка «ещё» по
`next_cursor`. Фасеты (результат, клиент с группой «Не описан» под ключом `client_id == ""`,
метод) и гистограмма по минутам считаются по загруженным записям; клиенты
группируются по стабильному `client_id`, а подпись имени берётся отдельно по
id из события или снимка. Клик по фасету клиента превращается в токен
`client:<name>`, который разрезолвится обратно в `client_id`; подпись
напоминает, что счётчики не по всему журналу. Автообновление каждые 5 с с
кнопкой «Пауза»; признаки `gap` и `ingestion.stale` показываются. Таблица:
время, клиент (имя или «не описан» + IP), назначение, результат. Панель
деталей фиксированной per-переменной ширины с пределами `--detail-w`
(280–520): поля запроса, для отказа — объяснение из
`/inspector/events/{id}/explain` и действия — «Разрешить домен» (через
`addDomainToClientPolicy` из `draft/edits.ts`) для `not_in_allowlist`,
«Описать IP как клиента» для неизвестного источника (переход в Клиенты на
тот же список неописанных источников), для разрешённого и admin — «Запретить
домен для всех» (добавление в `settings.blocked_domains`).

Аудит. История административных действий по дням с фильтрами (все /
применения / входы / учётки — по `action`) и поиском по актору; подгрузка по
`next_cursor`. Имена `action` и категории берутся из таблицы `audit/actions`
(каждая строка, записываемая Go-сервером, имеет русское название). Деталь:
заголовок и тип по `action`, кто, когда, объект (`entity_id`). Для
`create_revision` admin видит «что изменилось» из
`/revisions/{id}/preview` (`summary`) и статус операции из
`RevisionSummary.latest_status` (`/revisions`); менеджеру preview
недоступно — только ревизия. Подпись: аудит хранит 90 дней или 5 000 событий;
пароли и содержимое запросов не записываются.

Аккаунты, Настройки — заглушки «Раздел появится в следующем срезе» внутри
того же каркаса. Справка рабочая: оглавление из
`GET /api/v1/help` и статья из `GET /api/v1/help/{slug}`, Markdown рендерится
безопасно (без `dangerouslySetInnerHTML` с сырым HTML): заголовки, списки,
fenced code, inline `code`, **bold**, *italic*, ссылки. Ссылки `help:<slug>`
переходят внутри раздела; внешние ссылки открываются в новой вкладке с
`rel="noreferrer noopener"`.

## Общие компоненты

Диалог подтверждения (`ConfirmDialog`), пустое состояние (`EmptyState`),
аварийное состояние (`ErrorState` — API недоступно или 503), тосты (`Toast`).
`ThemeProvider` владеет предпочтением темы; `useOperationRecovery` продолжает
чтение известной операции после потери связи. `api.ts` отделяет сетевой
отказ и таймаут от HTTP/API error; стабильный код ошибки (`ApiError.code`)
пробрасывается в `applyFlow` без строкового разбора.

## Вход и bootstrap

Экран входа и bootstrap сохраняют работоспособность в новом стиле: карточка с
логотипом KRAKEN, форма входа, индикатор связи, серверные ошибки. Сессия,
CSRF и обработка 401 (переход на экран входа после `/session`) не изменились.

## Роли и область

Admin видит все разделы. Manager видит свою область (клиенты, политики,
журнал, аудит по области, свои логины прокси) и Справку; Настройки ему
недоступны. Роль и `permissions` приходят в `session response`, не берутся из
`localStorage`. Сервер фильтрует списки и запрещает правку вне области
([ADR 0016](../adr/0016-admin-and-manager-roles.md)).

## Проверки

Логика каркаса (`shell/layout.ts`, `shell/nav.ts`, `draft/applyFlow.ts`)
покрыта unit-тестами vitest в `src/web/tests/unit`. E2e на ключевые потоки —
отдельный срез.
