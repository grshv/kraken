# Web-интерфейс

Описывает текущее устройство каркаса панели. Вид и поведение — по
согласованному прототипу [prototype/kraken-ui.html](prototype/kraken-ui.html);
решения — в [decisions](decisions.md).

Закрытая русскоязычная рабочая панель. Цель — управлять доступом клиентов и
находить запросы/отказы, без маркетингового текста и повторения архитектурной
документации.

## Компоновка

React/Vite использует готовые компоненты [shadcn/ui](https://ui.shadcn.com/docs/installation/vite)
(New York, Radix). Исходники компонентов в `src/web/src/components/ui`,
конфигурация CLI — `src/web/components.json`. Локальные компоненты в embedded
bundle: runtime CDN и Node server не нужны. Экраны собираются из компонентов shadcn (Card, Badge, Table, Tabs, Switch,
RadioGroup, ToggleGroup, Checkbox, Select, Accordion, Collapsible, DropdownMenu,
Popover, Tooltip, Command, AlertDialog, Sheet, Sidebar, Resizable, ScrollArea,
Calendar, Chart на recharts, Sonner) и общих обёрток `src/web/src/components/kraken`
(панели, строка списка с подсказкой полного текста, инспектор, callout, chip, KPI,
key-value, поле формы и строка настройки на shadcn Field, `Timestamp`) с
утилитами Tailwind CSS 4. Токены цветов, статусов и шкала текста — `theme.css`;
`style.css` в cascade layers держит только базовые сбросы, skip link и стили,
которые библиотеки (sonner, Radix ScrollArea) вставили бы inline-тегом `<style>`:
CSP панели (`style-src 'self'`) такие теги не пропускает, поэтому цвета графиков
передаются CSS-переменными через свойство `style`. Вид сверяется скриншотами с
прототипом.

Каркас «инспектор»: шапка по колонкам, колонка разделов (rail, 48 px), панели
раздела в одной shadcn Resizable-группе, нижняя панель черновика и панель
проверки справа. Все правки идут в черновик; применение — отдельная операция.
Минимальная ширина окна — 1024 px.

Тема — нейтральные серые поверхности и один акцент (индиго) только для действий,
выбора, фокуса и активного раздела; статусы — зелёный, красный, янтарный.
Светлая и тёмная. Один шрифт IBM Plex Sans (`@fontsource/ibm-plex-sans`) с
табличными цифрами для текста, IP и доменов, без моноширинного. Три размера
текста: 13, 14 и 20 px. Метки сущностей — цветное слово или иконка, не плашки.
Время — московское (МСК), точное значение с датой в подсказке (`Timestamp`).
Ревизия везде показывается номером `r-<number>` (`revisionLabel`), UUID — только
в деталях. Lucide icons. Внешнего font CDN нет; лицензии в `public/licenses`.
Поддерживаются reduced motion, skip link, видимый keyboard focus. Начальная тема —
светлая независимо от ОС; тёмная включается в меню профиля и сохраняется.
Favicon — собственный кракен (`public/kraken-mark.svg`), светлый или тёмный по
`prefers-color-scheme`.

## Шапка

Колонки: логотип-кракен над колонкой разделов, надпись KRAKEN заглавными с
разрядкой, поиск ⌘K по центру окна (равные боковые колонки), индикатор состояния справа. Логотип —
геометрический кракен без плашки, `currentColor` наследует цвет темы. Поиск
открывает командную палитру; индикатор состояния («● Работает») — popover с
полями из `/status` и `/squid/metrics` (загружаются при открытии): заголовок
«Squid работает / не отвечает» с давностью проверки, затем экземпляр, ревизия и
время применения, версия и аптайм Squid, порты, сбор журнала, занятость тома
данных; ссылки «История применений» и «Настройки экземпляра» (admin, открывает
порты). Поле без данных скрывается или показывает прочерк. При недоступном
Squid над панелями — полоса с пояснением, что Kraken перезапускает его с последней
рабочей ревизией.

## Левая колонка и профиль

Разделы из `navItems(role)`: main — Клиенты, Политики, Журнал, Аудит, Аккаунты;
bottom — Справка и (только admin) Настройки. Иконки с подсказкой названия,
активный раздел — заливка и полоса акцента слева; новые уведомления — точка на
иконке Клиентов (число — в подсказке). Менеджер не видит Настройки, а в
Аккаунтах видит только свои логины прокси. Внизу — аватар с меню профиля (имя,
роль, «Мой аккаунт», «Сменить пароль», «Завершить другие сессии», тема, выход).
Меню закрывается по Outside click, Escape и выбору действия. «Мой аккаунт»
открывает в Аккаунтах свою учётную запись. «Сменить пароль» —
диалог с текущим паролем и новым дважды (`PUT /session/password`); правила
нового пароля (12–1024 байт, не совпадает с текущим) проверяются и в форме,
ошибка неверного текущего пароля — под его полем. Эта сессия остаётся, другие
сессии пользователя завершаются.

## Панели переменной ширины

Разделы собираются только из общих панелей `components/kraken/layout.tsx`:
`ListPane` слева (в Журнале — фильтры), `InspectorPane` в центре и `DetailPane`
справа (в Журнале — выбранный запрос или домен). Своих колонок фиксированной
ширины в разделах нет. Панели — shadcn Resizable (`react-resizable-panels`):
шелл держит группу `kraken-main`, `ListPane` добавляет в неё свою панель с
разделителем, деталь журнала — вложенная группа `kraken-request-panels`.
Пределы: список 220–440 px, деталь 280–520 px, центр не уже 500 px; раскладка
запоминается библиотекой (`useDefaultLayout`). Разделитель доступен с клавиатуры.
Строка списка обрезает текст и показывает его полностью в подсказке; фильтры-
категории — выпадающий список под поиском, а не ряды чипов. Ошибки связи и API —
полоса над панелями (слот `banner` шелла), а не колонка.

## Командная палитра

⌘K / Ctrl+K: фильтрация по подстроке, навигация стрелками, Enter выполняет,
Escape закрывает. Действия разрешаются через `paletteIntent(id, role)` из
`src/web/src/shell/paletteIntent.ts`; действие, для которого intent равен null
(например, «Запретить домен для всех» для менеджера), в списке не показывается.
Группы «Действия», «Клиенты» (клиенты черновика, поиск по имени и сетям,
выбор открывает клиента через intent `client:<id>`), после ввода текста —
«Домены» (домены журнала за 24 ч из `/events/domains` с клиентами, которые к
ним обращались, плюс домены политик, свои домены клиентов и запреты; выбор
открывает Журнал на виде «Домены» с этим доменом) и «Запретить для всех»
(admin; `blockDomainsForAll` в черновик), затем «Политики» и «Разделы».
«Новый клиент» открывает форму создания клиента в разделе Клиенты; «Новый логин
прокси» — форму создания логина прокси в разделе Аккаунты; «Запретить домен для
всех» (только admin) — строку «Запрещено для всех» в Политиках; «Проверить и
применить черновик» открывает панель проверки справа. Переданный секции intent одноразовый: секция
обрабатывает его в эффекте и сбрасывает.

## Черновик и применение

Нижняя панель черновика видна, когда `/status.has_unapplied_changes` истинно:
отметка «Есть неприменённые изменения» с пояснением, «Сбросить черновик» (с
подтверждением) и «Проверить и применить». Пустой черновик панель не показывает.
Под каждым изменением в панели проверки — строки `details` из preview: что именно
поменялось (поля, добавленное и удалённое в списках; у удалённого объекта — что
у него было); изменение только «Запрещено для всех» называется правилом, а не
настройками Squid. После применения список остаётся с заголовком «Применено в
r-N» и кнопкой «Открыть в аудите».
Панель проверки (sheet справа, до 620 px) по прототипу: заголовок с крестиком и
работающей ревизией `r-<номер>`; список изменений из `changes` свежего preview
(загружается при открытии; по объекту: клиент, каждая политика, настройки Squid,
режим и expert-секция, TLS-профили; маркер +/−/~ по тексту строки) с кнопкой
«Отменить» у каждой строки, кроме TLS-профилей: `revertChange` возвращает этот
объект к действующей ревизии по правилам из [decisions](decisions.md) и
сохраняет черновик, превью перечитывается; без `changes` (менеджер, старый
ответ) — строки `summary` без кнопок; «Влияние на трафик» из
`/inspector/draft-impact` (клиенты, у которых разрешённые за 24 ч запросы начнут
получать отказ, число исчезающих отказов, напоминание, что открытые туннели не
разрываются); свёрнутые «Изменённые фрагменты squid.conf» — только изменённые
строки `config_diff` с двумя строками контекста. Шаги применения появляются, когда
применение начато. Шаги revision → validate → apply идут по реальному API:

- `POST /revisions` с `expected_draft_version`;
- для admin — `GET /revisions/{id}/preview` за `expected_applied_revision`;
  менеджеру preview недоступен (`403 admin_required`), тогда `expected`
  берётся из ответа `POST /revisions`, если поле есть, иначе `null`;
- `POST /operations` (`validate`, затем `apply` с `validation_operation_id`);
- опрос `GET /operations/{id}` до терминального статуса;
- `Idempotency-Key` — случайный (UUID, fallback на случайную строку 16+ символов).

Состояния `applyFlow`: idle, running (с шагом), done, failed (с кодом),
conflict, rolled_back. Конфликт (`409`) показывает кнопку «Обновить черновик».
`draft_out_of_scope` (403) — понятный текст: в черновике есть изменения вне
области менеджера, применить целиком может только администратор. Откат
(`rolled_back`) — Squid вернулся к прежней ревизии, трафик не прерван.
При ошибке Squid (rejected) текст ошибки не показывается, в нём могут быть
секреты. При потере связи после получения operation ID опрос возобновляется
через `useOperationRecovery`, мутация не повторяется.

## Разделы

Клиенты. Список с поиском (имя, IP, домен), выпадающим фильтром (все клиенты / с
отказами за 24 ч / изменены в черновике, с числом), sparkline столбиками по часам и метками «новый/изменён/удалён» по `entityMarks(active,
draft)`; отдельная группа «Неописанные источники» из `/inspector/unknown-sources`
(назначения и давность) с переходом в форму создания; источники, уже покрытые
клиентом действующей конфигурации, в группу не попадают. В форме создания из
источника — «Просмотрено», «Игнорировать» и «Снять отметку» (`POST
/notifications/marks` с `source/<ip>`); игнорируемые источники скрыты из группы до
нажатия «Показать игнорируемые (N)», просмотренные показаны приглушённо. Счётчик на иконке
«Клиенты» — число новых уведомлений из `/notifications` (отказанные домены,
которых нет в итоговом списке клиента, и неописанные источники за 7 дней). В шапке клиента — давность последнего запроса. Инспектор на
пять вкладок: Обзор (блок с новыми уведомлениями клиента — отказанные домены, которых нет в
итоговом списке, за 7 дней; «Разобрать» ведёт в «Доступ», «Отметить просмотренными» ставит общую
отметку, и блок пропадает до следующего нового домена; KPI, график
«Трафик за 24 часа» по 15-минутным интервалам с подсказкой при наведении, топ
назначений из `/inspector/clients/{id}/stats`, карточка правил с итоговым списком,
подключёнными политиками, своими доменами, запретами поверх них и подключением,
последние запросы), Доступ (режим: список доменов / весь веб / нет доступа;
при «весь веб» списки скрыты, но сохраняются; таблица «Отказанные домены» из
`/notifications?client_id=…`: фильтр Новые / Просмотренные / Игнор / Все с
числом, поиск, выбор всех на странице, по 50 строк с «Показать ещё»; у каждой
строки «Разрешить» и меню «⋯» (Просмотрено, Игнорировать, В новые, Запретить для
всех); пока ничего не выбрано — подсказка про массовые действия; пачкой —
«Разрешить» (`addDomainsToClient` — в свои домены клиента, новые помечаются просмотренными),
«Просмотрено», «Игнорировать», «В новые», для администратора «Запретить для
всех» (`blockDomainsForAll`, помечаются игнорируемыми); домен, уже добавленный в
черновик, помечен «в черновике» до применения; число новых — на вкладке;
карточка «Политики»: подключённые наборы с числом доменов и другими клиентами,
«Открыть» (переход в Политики), отключение крестиком, «Подключить…» из
остальных (`attachPolicy`/`detachPolicy`); карточка «Свои домены» — редактор
доменов `parseDomainInput`/`mergeDestinations` с запросами клиента за 24 ч и
меткой «не используется» из `/inspector/clients/{id}/hits`:
таблица, под ней поле добавления с переключателем «с поддоменами» (включён;
`*.x` всегда с поддоменами);
шаблоны из `/inspector/domain-templates`; «Сделать политикой…» переносит свои
домены в новую политику, подключённую клиенту (`shareClientDomains`);
карточка «Итоговый список» — `effectiveDestinations`, у каждой строки источник:
«свой» и/или имена политик),
Источник и подключение (имя, описание, тип, включён; адреса по строке с размером
сети, сохраняются при потере фокуса, через `parseNetwork`
с проверкой пересечения `networksOverlap` и, для менеджера, вхождением в его
сети через `networkWithin`; подключение HTTP или TLS с логином прокси из
`/proxy-accounts` — `setClientConnection` ставит `tls_profile_id` и логин, при
необходимости создаёт TLS profile с сертификатом `proxy-server`; если
`/certificates` не содержит `proxy_server`, вариант TLS недоступен с пояснением
и ссылкой на справку, как и без логинов прокси, `tlsUnavailable`), Запросы (тот же компонент, что раздел Журнал, суженный до
клиента: виды «Запросы» и «Домены», период, результат, поиск, деталь рядом с
таблицей и «Открыть в журнале»; «Все» у топа назначений и последних запросов
открывает вкладку на нужном виде, KPI запросов и отказов — Журнал на этих
запросах), История (изменения клиента:
режим, подключение, подключённые и отключённые политики, изменения итогового
списка — по парам применённых ревизий и черновику, `clientChanges`; автор — из
аудита `create_revision`).
Создание клиента — форма в три шага (кто: имя, тип, адреса; куда: список
доменов — отметки политик и свои домены с шаблонами, весь веб или пока без
доступа; подключение: HTTP без логина или TLS с логином прокси, с теми же
условиями доступности TLS) рядом со списком, в том числе из неописанного IP; дублировать, отключить,
удалить с подтверждением.

Политики. Для администратора первая строка списка — «Запрещено для всех»
(глобальный запрет, `settings.blocked_domains`, редактор `BlockedDomainEditor`;
intent `blocked-domains` открывает её). Далее список именованных наборов доменов
без режима и подключения (это свойства клиента): число подключивших клиентов («не подключена» без них),
доменов и запросов за 24 ч. Деталь с тем же редактором доменов
(метка «не используется» — ноль запросов за 7 дней), попаданиями 24 ч / 7 дней
из `/inspector/policies/{id}/hits`, карточкой «Чего не хватает» (отказанные
домены клиентов политики с режимом «список», которых нет в их итоговом списке,
`missingDomains`; «Добавить» кладёт домен в эту политику) и клиентами
политики — кнопками перехода к клиенту. Создать, дублировать, переименовать (кнопка в шапке, имя правится на месте), удалить (только если ни один клиент не подключил; менеджер
не меняет политику с чужими клиентами — кнопка неактивна с пояснением).

Все правки клиентов и политик идут в черновик через `PUT /configuration/draft`
с `expected_version`; `409 revision_conflict` → тост и перечитывание черновика
и действующей конфигурации; коды `source_outside_scope`, `source_overlap`,
`policy_shared_out_of_scope`, `username_taken` показываются у поля по
`ApiError.code`. Кнопка «Сбросить черновик» в нижней панели вызывает
`DELETE /configuration/draft` (с подтверждением). Действующая конфигурация для
сравнения меток приходит из `GET /configuration/active`; менеджер видит свою
область, действия вне области недоступны. Пустые состояния (нет клиентов, нет
политик) показывают создание первого объекта, в том числе из неописанного
источника.

Журнал (`log/Journal.tsx`, тот же компонент во вкладке «Запросы» клиента). Два
вида — «Запросы» (по одному) и «Домены» (запросы по домену из `GET
/events/domains`: запросы, разрешено, отказов, источников, объём, последний
запрос). Слева фильтры (`log/filters.ts`): период — 1 ч / 24 ч (по умолчанию) /
7 дн или календарь с временем начала и конца по МСК (не длиннее 7 суток);
результат (все / отказы / разрешено, `failures_only` / `allowed_only`);
отметками — клиенты с поиском (включая «Не описан», `unmatched=true`), причины
отказа (`deny_reason`) и методы; повторяемые `client_id`, `method`, `deny_reason`
означают «любой из». Счётчики у каждой группы — из `GET /events/facets` без
выбора этой группы. Поиск «Домен или IP»: адрес — `source_ip`, иначе подстрока
`destination`; выбранный домен — отдельная отметка. Активные фильтры — кнопки с
крестиком над таблицей; «Сбросить» снимает всё, кроме периода. Состояние
журнала — в адресе (`#log=…`), другие разделы открывают его intent
`log:<состояние>`. Сводка над таблицей (сворачивается, состояние в
`localStorage`): запросы, отказы, объём и неописанные источники из `summary`
`/events/domains`, график разрешённых и отказанных по времени из гистограммы
фасетов, топ-5 доменов и клиентов; каждая цифра сужает журнал до того, что она
считает. Автообновление каждые 5 с с кнопкой «Пауза»; ввод поиска ждёт 250 мс.
Таблица запросов: время (только время, если период в пределах суток), источник
(клиент и IP), назначение, метод, объём (пока деталь закрыта), результат с
кодом, `×N` для схлопнутых записей и причиной отказа; «Показать ещё» по
`next_cursor`; признаки `gap` и `ingestion.stale` — «сбор журнала отстаёт».
Клавиши: j/k — строки, a — разрешить домен клиенту, Esc — закрыть деталь.
Деталь запроса: результат, источник (переход к клиенту), назначение; для отказа —
«Почему отказано» одной фразой по `/inspector/events/{id}/explain` (`whyText`:
защита, запрещено для всех, неописанный источник, выключен, логин, режим «нет
доступа», домена нет ни в своих доменах, ни в политиках «…»; разрешённый сейчас —
«исторический отказ») со ссылкой на статью справки; отметка, если разрешение уже
в черновике; «Разрешить» — «Только для клиента» (`addDomainToClient`) или «В
политику «…»» с перечнем затронутых клиентов (`addDomainsToPolicy`; менеджеру
недоступно для политики с чужими клиентами); «Описать IP как клиента» для
неописанного источника; для admin «Запретить для всех» (`blockDomainsForAll`),
кроме отказов защиты; свёрнутые «Технические данные» (результат Squid, повторы,
ревизия). Деталь домена: счётчики, порты, источники (до 20, остальные числом),
«Показать запросы» (вид «Запросы» с этим доменом), «Разрешить» для клиентов,
получивших отказ и не имеющих домена в итоговом списке черновика, и «Запретить
для всех».

Аудит. История административных действий по дням: фильтры (все /
применения / входы / учётки — по `action`) над поиском по имени пользователя;
подгрузка по `next_cursor`. Заголовок строки — суть изменения из `detail`
(«Клиент «x» изменён»), под ним название действия и автор; без `detail` —
название действия. Имена `action` и категории берутся из таблицы `audit/actions`
(каждая строка, записываемая Go-сервером, имеет русское название). Деталь:
заголовок и тип по `action`, кто, когда, объект (ревизия как `r-<номер>`,
«черновик», иначе `entity_id`). У ревизии и изменений черновика — карточка «Что
изменилось» тем же списком с маркерами +/−/~ (`ChangeList`), что и в панели
проверки: для `create_revision` admin видит `summary` из
`/revisions/{id}/preview` и статус операции из `RevisionSummary.latest_status`,
менеджер — `detail`; для `update_draft`/`discard_draft` — строки `detail`, а у
записей без `detail` пояснение, что подробности не записаны. У прочих действий
`detail` — строка «Что» в карточке.

Справка: оглавление из
`GET /api/v1/help` и статья из `GET /api/v1/help/{slug}`: первый абзац — подзаголовок
под названием, при нескольких разделах `##` — карточка «Содержание» с переходом к
разделу (`splitArticle`), текст в колонке до 720 px; Markdown рендерится
безопасно (без `dangerouslySetInnerHTML` с сырым HTML): заголовки, списки,
fenced code, inline `code`, **bold**, *italic*, ссылки. Ссылки `help:<slug>`
переходят внутри раздела; внешние ссылки открываются в новой вкладке с
`rel="noreferrer noopener"`. Статья с полем `screen` (раздел интерфейса из
front matter) показывает в шапке кнопку «Открыть «Раздел»», если раздел виден роли
(менеджеру — не Настройки).

Аккаунты. Две группы — «Панель управления» (`/users`, admin only) и «Логины
прокси» (`/proxy-accounts`, сервер фильтрует по области менеджера). Менеджер
видит только «Логины прокси». Создание пользователя (роль admin/manager) и
прокси-логина — форма с полем пароля; пароль не показывается и не сохраняется
после отправки. Смена пароля (диалог из кнопки в шапке), блокировка/разблокировка пользователя
(кнопка в шапке) и включение/отключение логина — `PATCH /users/{username}` и
`PATCH /proxy-accounts/{username}`. Для пользователя панели по прототипу: слева
карточка «Роль» (два варианта рядом и права только текущей роли по
[ADR 0016](../adr/0016-admin-and-manager-roles.md)), справа «Входы» и «Последние
действия» (`GET /audit?actor=`, 5 строк, «Весь аудит»), ниже на всю ширину
«Сессии» таблицей (текущая первой); последнего активного admin
нельзя понизить или заблокировать (`canDemote`/`canDisable` из
`src/web/src/accounts/rules.ts` дизейблят кнопку, сервер тоже отказывает). Для
менеджера — область: сети (`parseNetwork` из `clients/networks.ts`) и клиенты
из черновика через `GET`/`PUT /users/{username}/scope` (телом собирает
`buildManagerScopeBody`). Для логина прокси — где используется (клиенты
черновика с этим `proxy_username`) и владелец (`owner`). Карточка «Входы»
пользователя панели — последний вход и неудачные за 24 ч из аудита (`login`,
`login_failed` по актору) и пороги ограничения входа; «Сессии» — живые сессии из
`GET /users/{name}/sessions`: устройство (браузер и ОС из User-Agent,
`deviceLabel`; полный User-Agent — в подсказке), адрес, начало и активность,
метка «эта», «Завершить» у чужих сессий и «Завершить другие» (у другого
пользователя — «Завершить все»). У логина прокси — показатели за 24 ч из
`GET /proxy-accounts/{name}/activity` (запросы и время последнего, неверный пароль,
отказы политики, число адресов) и «С каких адресов» с подсказкой, если с адреса
идут попытки с неверным паролем (вероятно, на устройстве прежний пароль).

Настройки (только admin). Слева список разделов, справа деталь. Все правки —
в `snapshot.settings` черновика через `PUT /configuration/draft`
(`expected_version`, `409` → тост и перечитать), изменённое поле помечается
«в черновике». «Запрещено для всех» перенесено в Политики; intent
`setting:<id>` открывает раздел (из индикатора состояния — порты). Разделы:
«Встроенная защита» (информационные строки и переключатель
`allow_private_destinations`); «Вышестоящий прокси» (`upstream_proxy` —
вкл/выкл, один IP-адрес без префикса и порт через `parseUpstream`, `exclusive`); «Приватность» (`hide_client_address`);
«Экземпляр и порты» (имя экземпляра только для чтения из
`/status.instance.name`, подсказка `KRAKEN_INSTANCE_NAME`; `safe_ports` и
`connect_ports` через `parsePortList` из `src/web/src/settings/units.ts`;
порты прокси только для чтения); «Сертификаты TLS» (`/certificates`: кому
выдан, имена, издатель, до когда, сколько осталось, предупреждение при < 30
дней); «DNS» (`dns_nameservers` — IPv4/IPv6 через запятую или пробел через
`parseNameservers` из `src/web/src/settings/units.ts`, пусто = DNS контейнера;
TTL через `parseDuration`/`formatDuration`), «Таймауты и лимиты», «Кеш»,
«Журналы» — поля Settings с `parseDuration`/`formatDuration` для секунд; «squid.conf вручную» —
предупреждение об аварийном режиме, моноширинный редактор `expert_config`,
кнопка «Вставить шаблон» из `/configuration/expert-template`; ошибки
валидации сервера показываются у редактора.

## Общие компоненты

Диалог подтверждения (`ConfirmDialog`), пустое состояние (`EmptyState`),
аварийное состояние (`ErrorState` — API недоступно или 503), тосты (`Toast`).
`ThemeProvider` владеет предпочтением темы; `useOperationRecovery` продолжает
чтение известной операции после потери связи. `api.ts` отделяет сетевой
отказ и таймаут от HTTP/API error; стабильный код ошибки (`ApiError.code`)
пробрасывается в `applyFlow` без строкового разбора.

## Вход и bootstrap

Экран входа и bootstrap сохраняют работоспособность в новом стиле: карточка с
логотипом и надписью KRAKEN в стиле шапки, форма входа, индикатор связи, серверные ошибки. Сессия,
CSRF и обработка 401 (переход на экран входа после `/session`) не изменились.

## Роли и область

Admin видит все разделы. Manager видит свою область (клиенты, политики,
журнал, аудит по области, свои логины прокси) и Справку; Настройки ему
недоступны. Роль и `permissions` приходят в `session response`, не берутся из
`localStorage`. Сервер фильтрует списки и запрещает правку вне области
([ADR 0016](../adr/0016-admin-and-manager-roles.md)).
