# Требования

Требуемое поведение и критерии приёмки. Статус реализации — в [status](../status.md).
Все примеры синтетические.

## Продукт

Web-панель управления исходящим доступом через Squid, поставляемая одним
Docker-образом. Размещение — Linux-узел с Docker. Клиент прокси — устройство,
сервер, контейнер, адрес, сеть или именованная группа; VM не является сущностью
продукта. Клиенты используют явный HTTP/HTTPS forward proxy, включая APT.
Главная ценность — управление доступом и понятная диагностика отказов.
Визуальные настройки дополняются экспертной секцией squid.conf.

## Основные сценарии

- Оператор создаёт первого администратора командой в контейнере, без пароля по
  умолчанию и публичной регистрации.
- Администратор описывает клиента (адреса, сети, логин прокси) и выбирает режим:
  список доменов (свои домены и любое число подключённых политик — именованных
  наборов доменов), весь веб или отсутствие доступа.
- Отказ в журнале объясняется по текущим правилам; домен разрешается из журнала
  или карточки клиента; неописанный источник превращается в клиента.
- Все правки идут в черновик и не влияют на трафик. Проверка запускает реальный
  Squid parse; применение проверяет наблюдаемый fingerprint и при сбое откатывает.
- История показывает применённые ревизии; откат — отдельная проверенная операция.
- Администратор настраивает порты, DNS, таймауты, кеш, вышестоящий прокси,
  «запрещено для всех», скрытие адреса клиента и экспертную секцию.
- Менеджер управляет только своими клиентами, сетями и логинами прокси
  ([ADR 0016](../adr/0016-admin-and-manager-roles.md)).
- Оператор сбрасывает пароль, управляет пользователями, отзывает сессии и делает
  копию данных командой `kraken` внутри контейнера.

## Пользователи и пароли

Роли панели — admin и manager. Сервер проверяет права и область на каждом запросе;
скрытая кнопка в UI проверкой не считается. Последнего включённого admin нельзя
отключить или понизить ни через API, ни через CLI.

Пароль никогда не сохраняется как исходное значение: в БД только salted Argon2id
PHC verifier. Пароль не попадает в argv, env, файлы и логи. Сброс атомарно меняет
verifier, отзывает сессии пользователя и пишет аудит; уже начавшийся вход не
обходит сброс.

Аутентификация прокси по логину и паролю — отдельный способ идентификации клиента.
Успешный логин сам по себе доступа не даёт: доступ определяет режим и список клиента.
Клиент с логином требует TLS к прокси и адреса источника. Клиентские сертификаты
исключены.

## Режимы конфигурации

Structured: клиенты и политики компилируются из форм. Expert: пользовательская
секция squid.conf заменяет визуальные правила доступа; они сохраняются, но не
действуют, и это видно в UI. Expert-секция принимает только директивы из allowlist;
пути, listeners, файлы-параметры, helpers и `sc_` имена закрыты. Ошибка parse
показывает номер строки без вывода Squid
([ADR 0007](../adr/0007-general-clients-expert-configuration.md)).

## TLS и ограничения

HTTPS панели обязателен. HTTPS сайтов — только сквозной CONNECT: клиент проверяет
исходный сертификат сайта, прокси не видит путь, заголовки и содержимое.
Кеширование — только обычного HTTP.

Forward proxy не заменяет VPN, firewall и запрет прямого egress. Source IP не
идентифицирует человека. Частные адреса назначения закрыты по умолчанию;
loopback, link-local и metadata закрыты всегда.

## Хранение

Внешней БД нет. Содержимое запросов не записывается — только адрес назначения,
результат и объём. Статистика и аудит хранятся до 3 лет, отдельные события — по
бюджету диска. Тяжёлые чтения не блокируют вход, применение и сбор событий;
нехватка места останавливает сбор событий раньше, чем мешает применению.

## Критерии приёмки

| ID | Сценарий | Результат |
| --- | --- | --- |
| AC-01 | Неизвестный источник в structured mode | Отказ без обращения к цели |
| AC-02 | Клиент «весь веб» | Доступ на разрешённые порты с защитными запретами |
| AC-03 | Клиент со списком доменов | Разрешённый домен доступен, чужой и IP-литерал запрещены |
| AC-04 | Неверная политика или конфиг | Активная ревизия не меняется |
| AC-05 | Сбой reload или verify | Проверенный откат либо явное degraded |
| AC-06 | Конкурентная правка черновика | Устаревшая версия получает конфликт |
| AC-07 | Падение только панели | Squid и открытые CONNECT продолжают работу |
| AC-08 | Loopback, link-local, metadata | Отказ во всех режимах |
| AC-09 | Нет сессии, CSRF или Origin | Сервер отклоняет изменение |
| AC-10 | Диагностика HTTPS-туннеля | Нет выдуманных путей и статусов сайта |
| AC-11 | TLS к прокси | Сертификат проверяется, plaintext downgrade закрыт |
| AC-12 | Сквозной HTTPS | Исходный сертификат сайта сохраняется |
| AC-13 | Копия и восстановление | Копия тома `/var/lib/kraken` восстанавливается в новый volume: вход, ревизия, политика, история |
| AC-14 | Отключение клиента | Новые запросы закрыты |
| AC-15 | Сброс пароля из CLI | Только новый verifier, сессии отозваны, старый вход не выпускает сессию |
| AC-16 | Настройки и expert mode | Меняется фактическая конфигурация Squid |
| AC-17 | История и откат | Сравнение, повторная проверка, отдельная операция и аудит |
| AC-18 | Сбой записи или падение | Кандидат не становится рабочим без подтверждения |
| AC-19 | Роли и область | Менеджер не видит и не меняет чужое; ответы вне области — по ADR 0016 |
| AC-20 | Аутентификация прокси | Логин определяет клиента, политика — доступ; неверный пароль не открывает прокси |
| AC-21 | Объяснение отказа | Журнал показывает причину по текущим правилам и действие для исправления |
| AC-22 | Порты установки | Listener HTTP/TLS нельзя сменить через черновик или старую ревизию |
| AC-23 | Принудительная остановка | После kill контейнера Squid стартует и применяет ту же ревизию |
| AC-24 | Нагрузка на хранилище | Чтение статистики во время записи событий не блокирует вход и применение |
| AC-25 | Нехватка диска | Сбор событий останавливается, применение отвечает ошибкой до записи, без частичного применения |
| AC-26 | Несколько политик у клиента | Открыто объединение своих доменов и подключённых политик; «Доступ» показывает итоговый список с источником строки; снимок старой схемы (одна политика с режимом) переводится без потери доступа |

## Пределы

Один узел не даёт HA; обновление образа прерывает оба процесса. Возможности Squid
зависят от версии и сборки образа; обещание «поддержан весь Squid» недопустимо.
Объём и исключения — в [status](../status.md).
