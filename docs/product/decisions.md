# Решения владельца и открытые вопросы

Здесь только то, что владелец подтвердил явно, и вопросы к нему.
Предложение исполнителя или ADR в статусе Proposed решением не является.
Новое решение добавляется в соответствующий раздел с датой.

## Продукт и развёртывание

- Один Linux-узел с Docker; VM — только пример (27.10.2026).
- База образа — Alpine; Squid собирается из последнего стабильного релиза upstream
  (GitHub, проверка подписи релиза по [ADR 0020](../adr/0020-squid-image-signed-release.md)) без изменения исходников и урезания возможностей.
  Toolchain и зависимости — актуальные LTS или последние стабильные версии
  ([ADR 0019](../adr/0019-alpine-upstream-squid.md), 29.10.2026).
- Один собственный image и один контейнер: Pebble, отдельные процессы Squid и
  Go-бинарника со встроенными UI, API и модулем применения. Host runner, systemd
  unit и отдельный edge container не нужны ([ADR 0006](../adr/0006-single-container.md), 27.10.2026).
- Весь код приложения и тестов — в `src/` (27.10.2026).
- Клиенты ходят через прокси в интернет, включая APT. Одним нужен весь HTTP/HTTPS,
  другим — только определённые ресурсы. Главная ценность — управление доступом и
  диагностика (27.10.2026).
- Клиент прокси — любое устройство, адрес, сеть или группа; VM не является
  сущностью интерфейса (27.10.2026).
- Простая архитектура SQLite и volume: не строить подсистему там, где достаточно
  короткой процедуры оператора. Необязательные идеи не становятся требованиями
  оттого, что упомянуты в документах (28.10.2026).
- Решение нигде не развёрнуто: совместимость со старыми volume разработки не
  поддерживается, легаси удаляется без миграций (29.10.2026).
- Состав сценариев expert-режима для типизированных настроек владелец поручил
  выбрать исполнителю: upstream proxy, запрещённые для всех домены, скрытие адреса
  клиента. Expert остаётся аварийным режимом (29.10.2026).
- Продукт называется Kraken; технические имена (бинарник, образ, модуль, env
  `KRAKEN_`, пользователь `kraken`) переименованы без совместимости (29.10.2026).
- Kraken — личный проект: лицензия и канал сообщений об уязвимостях не нужны;
  проверка заполнения настоящего тома (loop/volume) пропускается, достаточно
  ENOSPC на tmpfs (01.11.2026).
- Сканирование перед релизом проверяет каждую стадию сборки, а не только
  финальный образ: Go-исходники и бинарники, web-зависимости из lockfile (в
  образе они вшиты в бандл), Squid из исходников — по CPE в SBOM; итоговый SBOM
  финального образа проверяется целиком. Способ выбирает исполнитель (01.11.2026).
- Репозиторий публичный: бесплатные CodeQL, сканирование секретов с push
  protection и Dependabot alerts GitHub. CI разделён по частям — web, Go, образ
  Squid, образ панели, документация, CodeQL, еженедельное сканирование — и
  запускается только при изменении своей части. Зависимости обновляет Renovate.
  Squid — отдельный образ ([ADR 0020](../adr/0020-squid-image-signed-release.md))
  (01.11.2026).
- Публикация (01.11.2026): образ панели публикуется только после Go- и
  web-тестов того же коммита; изменение Squid проверяется вместе с панелью до
  публикации; опубликованные образы получают attestations GitHub (provenance и
  SBOM); еженедельное сканирование проверяет и последний релиз. Защита ветки
  `main` пока не включается — перед релизом.

- Хранение (29.10.2026): внешней БД нет, всё в SQLite на томе данных. Содержимое
  запросов не записывается — только адрес назначения host:port, результат и объём.
  История и статистика хранятся 1–3 года (агрегаты — 3 года, аудит — 3 года);
  отдельные события — сколько позволяет бюджет диска, по умолчанию 90 дней.
  Управляющие данные (пользователи, ревизии, применение, аудит) отделены от
  телеметрии: телеметрия не может заполнить диск и сломать применение, её потеря
  не ломает панель. Статистика читается из агрегатов, а не пересчётом событий;
  тяжёлые чтения не блокируют вход, применение и сбор событий.
- Нагрузка на хранилище (29.10.2026): ни чтение, ни запись панели не ждут БД дольше
  фиксированного дедлайна; занятое хранилище — ответ «повторите», а не зависание.
  Сбор событий дочитывает отставание без пауз; лог Squid не ротируется, пока сбор
  не прочитал старый файл (с жёстким пределом размера). Одинаковые события внутри
  порции (источник, назначение, результат) схлопываются в одну запись со счётчиком:
  поток повторов не раздувает журнал и диск, а статистика остаётся точной. Счётчики
  журнала для окон длиннее суток считаются по агрегатам.
- Раскладка данных (29.10.2026): постоянное состояние — один том в
  `/var/lib/kraken`: `data/` (управляющая БД и телеметрия), `certs/`, `log/` (логи
  Squid). Всё производное — конфиг Squid, экспорт логинов прокси, PID — Go
  пересоздаёт из БД в tmpfs `/dev/shm/kraken` при старте и применении. Журнал
  применения и последняя рабочая конфигурация хранятся в управляющей БД; файлов
  журнала и блокировки на томе нет. Пароль к менеджеру Squid нигде не хранится:
  новый случайный на каждый старт контейнера, только в tmpfs.
- Поставка и обслуживание (29.10.2026): продукт поставляется Docker-образом.
  Оператор управляет экземпляром через web-панель и CLI `kraken` внутри контейнера
  (`docker exec -it <контейнер> kraken …`): первый администратор, сброс пароля,
  пользователи, отзыв сессий, сертификат, копия данных, состояние. Makefile — только
  для разработки (проверки, сборка образа, integration). Python в проекте не
  используется: проверки документации и integration-тесты — на Go.

## Безопасность и доступ

- Web-управление защищено паролем. Пароль администратора хранится только как
  salted one-way hash; CLI reset меняет hash и отзывает сессии (27.10.2026).
- HTTPS сайтов — только сквозной CONNECT; серверный TLS к прокси сохраняется (27.10.2026).
- Процессы в контейнере не работают от root, где это возможно: root остаётся только у
  Pebble ради запуска Squid и панели под разными UID, без capabilities кроме
  SETUID, SETGID и KILL. Rootless Docker или userns-remap на хосте — дело установки
  ([ADR 0019](../adr/0019-alpine-upstream-squid.md), 29.10.2026).
- Визуальные настройки и экспертная секция squid.conf поддерживаются совместно
  ([ADR 0007](../adr/0007-general-clients-expert-configuration.md), 27.10.2026).
- Роли панели — администратор и менеджер; роль viewer убрана (29.10.2026, заменяет
  решение 27.10.2026 об admin и viewer). Администратор управляет всем. Менеджеру
  назначаются клиенты и сети: он видит и меняет только своих клиентов, их журнал и
  аудит, создаёт клиентов только в своих сетях, правит общую политику, только если все
  её клиенты назначены ему, и применяет черновик, только если тот касается лишь его
  клиентов. Менеджер создаёт логины прокси (они принадлежат ему) и управляет своими
  логинами и логинами, которыми пользуются только его клиенты; чужие логины ему не
  видны. Настройки, «запрещено для всех» и пользователи панели — только администратор.
  Граница доверия требует ADR до реализации.
- Proxy authentication по логину и паролю. Клиентские сертификаты, SSO/IdP и
  собственный CA не нужны ([ADR 0012](../adr/0012-local-users-and-proxy-passwords.md), 27.10.2026).
- Read-only выборка отчётов Squid manager и локальный service-update нужны для
  живого обзора; публичный manager и произвольные команды исключены
  ([ADR 0013](../adr/0013-read-only-squid-metrics.md), 28.10.2026).
- Количественные сведения о VM и пользователях в документы не записываются (27.10.2026).
- Секреты панели изолируются от процесса Squid разделением UID; сетевые гарантии
  проверяются раньше дополнительных fault-сценариев; избыточные пути совместимости
  удаляются ([план](../status.md#план-работ), 29.10.2026).

## Интерфейс

Действующие решения; заменённые варианты — в git log.

**Каркас и оформление**

- Интерфейс «инспектор» на компонентах shadcn/ui (28–29.10.2026): разделы
  Клиенты, Политики, Журнал, Аудит, Аккаунты, внизу Справка и Настройки; раздел —
  список и карточка; единые редакторы сущностей; полный итоговый конфиг доступен
  для просмотра; нет ложных изменений и полей портов контейнера. Справка внутри
  панели: сценарии, принцип работы, подключение машин. Начальный раздел — «Клиенты».
- Каркас (31.10–01.11.2026): колонка разделов на всю высоту со знаком-кракеном
  сверху и профилем снизу; кнопки разделов — скруглённые прямоугольники, выбранная
  на синей подложке, без левой отметки; маркер новых событий у «Клиентов» зависит
  от непросмотренных событий в доступной области. Шапка рабочей области — путь
  «Kraken / раздел», компактный поиск ⌘K и индикатор состояния: точка с цветом
  состояния и обычный текст, подробности по нажатию; имя экземпляра — в его панели.
  Тема переключается в меню профиля. Логотип — геометрический кракен без плашки;
  favicon — тот же кракен, светлый или тёмный по теме системы.
- Палитра (01.11.2026): фоны, рамки и текст ахроматические, без оттенка; один
  синий акцент — основные кнопки с синей заливкой и белым текстом, выбор и фокус.
  Янтарный — только предупреждения, зелёный — успех, красный — отказы. Цветные
  подложки относятся к состояниям и действиям, не к типам сущностей. Светлая и
  тёмная темы используют одни смысловые роли.
- Поверхности: навигация, рабочая область и всплывающие панели различаются фоном;
  тени только у наложений; контекстные блоки и формы на карточной поверхности,
  вложенные контролы темнее, выбранное светлее. Светло-синяя подложка шапки клиента
  отклонена.
- Типографика (31.10.2026): один шрифт IBM Plex Sans с табличными цифрами для
  текста, IP и доменов, без моноширинного; размеры 13, 14 и 20 px. Метки сущностей —
  цветное слово или иконка, не плашки; серым — только второстепенное. Время —
  московское (МСК), точное с датой — в подсказке.
- Списки и таблицы: строки боковых списков прямоугольные, выделение на всю ширину
  приглушённой синей подложкой (в светлой теме — голубой с синей иконкой) и
  сохраняется при наведении. Таблицы — общий прямоугольный контейнер с одинаковыми
  отступами; таблица в карточке без своей рамки и заливок, шапка карточки без
  обязательной линии. Статусы строк не повторяют выбранный фильтр. Длинные значения
  сокращаются с полным текстом в подсказке. Границы шапок соседних панелей совпадают.
- Панели — shadcn Resizable, ширина запоминается. Фильтр списка — кнопка со значком
  рядом с поиском, с вариантами, счётчиками и отметкой активного фильтра (так же —
  категория аудита).
- Окно поиска и действий — до 760×586 px с ограничением по экрану, строка ввода
  64 px с крестиком по центру, синее выделение результатов.
- Постоянные пояснения под заголовками не нужны; справочные сведения и права
  раскрываются по запросу ровной кнопкой на ширину строки. Шапки карточек, их
  действия и контролы строк настроек выровнены по центру.

**Клиент**

- Шапка клиента — одна строка: имя, последняя активность, описание и IP рядом с
  действиями; длинное сокращается с подсказкой.
- Обзор: метрики — матрица 2×2 с одинаковыми ячейками (подпись и значение,
  «Соединения» с подписью «сейчас»), кликабельность не меняет вид значения;
  назначения за 24 ч — основной рабочий список, нейтральные строки, красный только
  у счётчика отказов, «Разрешить» — синее действие; отдельный блок новых отказов за
  7 дней с переходом к разбору и массовой отметкой просмотра; разрешённые домены
  метками; последние запросы строками «время / назначение / результат». Данные
  обзора не переносятся только во вкладки.
- «Доступ»: текущий режим показывается компактно, выбор раскрывается.
  Предложения разрешить домен берутся из уведомлений об отказах списка за 7 дней с
  повторной проверкой черновика; защитные отказы и закрытые порты не объявляются
  недостающими доменами. Готовых наборов доменов («Ubuntu / Debian», «Python»,
  «GitHub») нет: домены задаются явно.
- Несколько политик у клиента (30.10.2026, заменяет решение о «своей политике»
  того же дня): политика — именованный набор доменов без режима и способа
  подключения. Клиент подключает любое число наборов и держит свои домены;
  открыто их объединение, и «Доступ» клиента показывает итоговый список с
  источником каждой строки. Режим доступа (список / весь веб / нет доступа) и
  подключение (HTTP или TLS с логином) — свойства клиента. Старые конфигурации
  переводятся автоматически: подключение и «весь веб» берутся из прежней
  политики клиента, политика остаётся набором.

**Журнал**

- Два вида — «Запросы» и «Домены» (запросы по домену с источниками и переходом к
  запросам), в Журнале и во вкладке «Запросы» клиента; период — пресеты и
  календарь; фильтры сохраняются в адресе; пресеты и сохранённые виды журнала не
  делаются.
- Строка над таблицей высотой 40 px: счётчик слева, метки фильтров с горизонтальной
  прокруткой, компактный период справа, полный период с годом и МСК — в подсказке.
  Постоянной подсказки клавиш нет, сочетания сохраняются.
- Поверхности: панель инструментов светлее, фильтры отдельно, заголовки колонок на
  серой подложке, данные — на тёмной вложенной; все ахроматические. Причина
  отказа важнее технического кода ответа.

**Черновик, аккаунты, уведомления**

- Все правки правил идут в черновик с нижней панелью и проверкой перед применением.
  Сохранение в черновик и немедленные изменения аккаунтов различаются до действия.
- Отмена одного изменения в панели проверки (30.10.2026): «Отменить» возвращает
  к действующей ревизии один объект — клиента, политику, настройки Squid или
  режим конфигурации с expert-секцией. Новая политика удаляется и отключается у
  клиентов черновика; удалённая возвращается без повторного подключения.
  Возвращённый клиент забирает из ревизии свои политики и TLS-профиль, если в
  черновике их нет. TLS-профили отдельно не отменяются — их меняет подключение
  клиента. Сводка изменений называет каждую политику отдельно.
- Проверка черновика учитывает область менеджера: чужие изменения не раскрываются,
  их наличие блокирует применение всего черновика, и это видно до нажатия
  «Применить». Отмена своего изменения сохраняет скрытые объекты и общие настройки.
  Это дополняет серверную проверку.
- Аккаунты: область менеджера рядом с ролью, права раскрываются; внутренние ID
  клиентов не показываются. Блокировка в списке — небольшой приглушённый значок с
  подсказкой и доступным именем, в карточке — красный статус со значком запрета.
- В строке политики название — первая строка, метка черновика — во второй рядом с
  количеством доменов.
- Уведомления (30.10.2026): без сложной логики. Уведомление не хранится, а
  вычисляется из статистики за 7 дней: домен, на который клиенту отказано и
  которого нет в его политике (отказы защиты и «запрещено для всех» не в счёт),
  и неописанный источник. Хранится только отметка: «просмотрено» (видно, но не
  считается новым) или «игнорировать» (скрыто из списков и счётчиков); снять
  отметку — вернуть в новые. Отметка общая для всех пользователей, с автором и
  временем, ставится пачкой и действует 90 дней. Новые отказы по тому же домену
  отметку не снимают. Менеджер видит и отмечает только уведомления своих клиентов
  и сетей.

## Исключено

Перечень исключённого ведётся в [status](../status.md#исключено-владельцем).
