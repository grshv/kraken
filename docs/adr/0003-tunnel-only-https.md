# ADR 0003: сквозной HTTPS и TLS к прокси

Статус: Accepted. Дата: 2026-10-27.

## Контекст

Нужны управление доступом и диагностика без чтения содержимого HTTPS-сайтов.
Шифрование соединения клиента с самим прокси — отдельная задача.

## Решение

- HTTPS панели обязателен.
- Клиент подключается к Squid по HTTP (3128) или TLS (3129). Подключение — свойство
  клиента; клиент с TLS не получает доступ через HTTP-listener.
- HTTPS сайтов проходит только сквозным `CONNECT`: клиент проверяет исходный
  сертификат сайта. Прокси не расшифровывает трафик, не выпускает сертификаты
  сайтов и не кеширует туннели.
- Expert-секция не открывает управление TLS сайтов и служебными listeners.

## Последствия

- Для HTTPS известны host:port, результат `CONNECT`, длительность и байты. Путь URL,
  заголовки и HTTP-статус сайта недоступны, и UI их не выдумывает.
- Кешируется только обычный HTTP.
- Сертификаты панели и TLS-listener прокси живут как обычные серверные сертификаты
  ([ADR 0013](0013-install-and-certificates.md)).
