# ADR 0007: роли администратора и менеджера

Статус: Accepted. Дата: 2026-10-29.

## Контекст

Панелью пользуются несколько человек, каждый отвечает за свою часть клиентов.
Тот, кто смотрит, обычно должен и чинить, поэтому роль только для чтения не нужна.
Конфигурация Squid одна на экземпляр, черновик один и применяется целиком, поэтому
область менеджера проверяется и при правке, и при применении.

## Решение

- `admin` управляет всем. Последнего включённого администратора нельзя отключить
  или понизить ни через API, ни через CLI.
- `manager` работает в своей области. Область — данные панели (таблицы
  `manager_networks`, `manager_clients`), а не снимок конфигурации; она читается
  из БД на каждом запросе.
  - **Сети** назначает администратор. Все адреса клиента, которого менеджер создаёт
    или меняет, лежат внутри его сетей.
  - **Клиенты** — назначенные администратором и созданные самим менеджером.
  - **Логины прокси** — свои (`owner`) и те, которыми пользуются только его клиенты.
  - **Политики** — видны те, что подключены к его клиентам, и неподключённые;
    менять можно, только если все клиенты политики — его.
- Только администратор: настройки Squid, «запрещено для всех», expert-секция,
  пользователи панели и их область, откат ревизий, текст squid.conf и снимки ревизий.
- Менеджер применяет или сбрасывает черновик, только если каждое изменение в его
  области. Чужие изменения не раскрываются; их наличие видно до нажатия
  «Применить» (`foreign_changes`).
- Журнал, аудит, статистика и поиск фильтруются сервером по области. Неописанные
  источники — только из его сетей.

| Ситуация | Ответ |
| --- | --- |
| Объект вне области | `404`, как несуществующий |
| Ручка только для администратора | `403 admin_required` |
| У политики есть чужие клиенты | `403 policy_shared_out_of_scope` |
| Адрес клиента вне сетей менеджера | `422 source_outside_scope` |
| Адрес пересекается с чужим клиентом | `422 source_overlap`, без имени клиента |
| Имя логина занято чужим логином | `409 username_taken`, без владельца |
| Черновик с чужими изменениями | `403 draft_out_of_scope` |

Курсор журнала и аудита содержит отпечаток области: смена области делает старый
курсор недействительным.

## Последствия

- Каждый обработчик фильтрует данные на сервере; скрытая кнопка в UI проверкой не
  считается. На каждый запрет из таблицы есть негативный тест.
- Менеджер узнаёт сам факт занятости имени логина или пересечения адресов — это
  минимальная утечка без имён.
- Смена роли и блокировка отзывают сессии; смена области — нет.
