# ADR 0002: типизированная политика, ревизии и проверяемое применение

Статус: Accepted. Дата: 2026-10-27.

## Контекст

Правка squid.conf текстом допускает injection, обход защитных правил и не даёт
предсказуемых diff и отката. Reload Squid с кодом 0 не доказывает, что действуют
новые правила. SQLite, файл конфигурации и процесс Squid не образуют общей
транзакции.

## Решение

- Конфигурация — типизированный снимок (клиенты, политики, настройки, режим,
  expert-секция). Его компилирует в squid.conf чистый пакет `internal/policy`
  без HTTP, SQLite и runtime.
- Правки идут в черновик и не меняют трафик. Применение — отдельная операция над
  неизменяемой ревизией с номером `r-<N>`.
- Применение: проверка снимка → рендер → `squid -k parse` кандидата →
  журнал `promoting` → атомарная замена файла → reload → проверка отпечатка ревизии
  через loopback canary → запись последней рабочей конфигурации (LKG) → `succeeded`.
  Ошибка после замены возвращает предыдущую LKG с той же проверкой и даёт
  `rolled_back` или `degraded`.
- Журнал применения и LKG хранятся в управляющей БД. Перед каждым запуском Squid
  `serve` восстанавливает незавершённое применение и пишет конфиг из LKG;
  `squid-start` ждёт этого. Без рабочей ревизии Squid стартует с deny-all.
- Операции идемпотентны по ключу; повтор с другим телом — конфликт. Одно
  применение за раз (`flock`), скрытой очереди нет.
- Откат — отдельная операция над прежней ревизией того же образа и компилятора.

## Альтернативы

- Текстовый редактор squid.conf: гибко, но UI не может гарантировать инварианты.
- Шаблон и перезапуск Squid: проще, но рвёт трафик и плохо переживает сбой.
- Сгенерированный файл как единственный источник: нет смыслового diff.

## Последствия

- Поддерживается только смоделированная часть Squid; остальное — через
  expert-секцию с allowlist ([ADR 0004](0004-expert-allowlist.md)).
- Неопределённость после сбоя разрешается консервативно: откат к LKG или `degraded`
  с блокировкой новых применений до восстановления.
- Тесты проверяют фактический доступ, а не только статус операции; fault-тесты
  прерывают запись на каждой границе журнала.
