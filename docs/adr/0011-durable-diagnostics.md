# ADR 0011: локальная история диагностики

Дата: 2026-10-27. Статус: Accepted — следующий срез по поручению владельца.

## Контекст и решение

Bounded tail не сохраняет историю и не позволяет стабильные страницы. Добавляем
нормализованный журнал SQLite и checkpoint по inode/device/offset. Фиксированные
access.log и его нумерованные ротации читаются порциями вне apply и HTTP запросов.
Checkpoint и события фиксируются одной транзакцией. Сырой текст не сохраняется;
поля разбираются до хранения. Некорректные/слишком длинные строки и утрата
непрочитанного файла учитываются как gap. Частичная строка ждёт завершения.

Клиент определяется по уникальному совпадению IP/CIDR активной политики при сборе.
Имя и ID сохраняются с пометкой policy_at_ingest, revision_id остаётся unknown.
Изменение клиента позднее не переписывает историю. Expert ACL может отличаться
от client labels: это подпись источника, не объяснение исторического решения.

Cursor привязан к виду журнала и фильтрам, содержит верхнюю границу страницы.
Новые записи не сдвигают просмотр старых страниц. Retention может удалять старое;
UI сообщает об ограничениях хранения. События: 30 дней от сбора, до 50 000 строк.
Audit использует существующие 90 дней/5000 строк. Ошибка сбора не объявляет
пустой журнал доказательством отсутствия запросов. После ADR 0012 API чтения доступны admin и viewer; mutations остаются admin-only.

## Альтернативы и последствия

Повторное чтение tail на каждый GET теряет историю при rotation и зависит от
частоты открытой панели. Внешний log cluster для одного узла пока не обоснован.
Локальный журнал не forensic archive: общий UID и доступ к volume позволяют
изменить данные. Не гарантируется отсутствие потерь при исчезновении всех
ротаций между чтениями или отказе диска. Crash/retry, privacy и rotation покрыты
[планом проверок](../plans/completed/diagnostics-history.md).
