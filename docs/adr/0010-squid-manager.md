# ADR 0010: manager Squid только на loopback

Статус: Accepted. Дата: 2026-10-28.

## Контекст

Access log описывает завершённые запросы, но не живое состояние Squid. Обзор должен
отличать отсутствие наблюдения от измеренного нуля. Reload сигналом невозможен из
другого UID ([ADR 0009](0009-separate-squid-uid.md)).

## Решение

- Рендер всегда добавляет служебные listeners: `127.0.0.1:3130` — canary для
  проверки отпечатка ревизии, `127.0.0.1:3131` — manager. Они не публикуются и
  закрыты для settings и expert-секции.
- На 3131 разрешены только GET с loopback: отчёты `info`, `counters`, `5min`,
  `active_requests` без пароля и `reconfigure`, `rotate` с паролем
  (`cachemgr_passwd` из tmpfs). Остальные действия отключены; manager на
  клиентских listeners запрещён до пользовательских правил.
- Панель опрашивает отчёты с лимитами: заголовки 16 KiB, весь опрос 2 с, кеш в
  памяти 2 с, без редиректов и proxy из окружения. API `/squid/metrics` отдаёт
  агрегаты; недоступные значения — `null`.
- `active_requests` содержит URL и логины. Они остаются только в памяти парсера;
  наружу выходит количество запросов без служебных.
- Трафик считается по `server.all` (обмен Squid с сайтами): клиентские счётчики
  включают опросы самого manager.

## Последствия

- Это доверенная связь процессов внутри контейнера, а не изоляция от кода панели.
- Вывод Squid, URL и учётные данные не попадают в API и логи.
- Ревизия, отрендеренная старым компилятором без этих listeners, получает служебное
  обновление (`service-update`) тем же путём применения.
