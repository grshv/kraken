# ADR 0016: администратор и менеджер

Дата: 2026-10-29. Статус: Accepted по решениям владельца 29.10.2026
([decisions](../product/decisions.md)).

Заменяет раздел о ролях admin и viewer из [ADR 0012](0012-local-users-and-proxy-passwords.md);
proxy accounts и auth helper из ADR 0012 остаются в силе.

## Контекст

Панелью пользуются несколько человек, каждый отвечает за свою часть клиентов.
Роль viewer не нужна: тот, кто смотрит, обычно должен и чинить. Конфигурация Squid
одна на экземпляр, черновик один и применяется целиком, поэтому область менеджера
должна проверяться и при правке, и при применении.

## Решение

### Роли

- `admin` — всё, как прежде. Последнего активного admin нельзя отключить или понизить.
- `manager` — только объекты своей области. Роль `viewer` удаляется; миграция переводит
  существующих viewer в manager с пустой областью.

Область читается из базы на каждом запросе, как роль и enabled. Изменение области не
отзывает сессии; изменение роли, блокировка и пароль отзывают, как раньше.

### Область менеджера

Назначения — данные панели, а не конфигурации Squid: отдельные таблицы SQLite, не snapshot.

- **Сети** — список CIDR, который назначает admin. Все source networks клиента,
  которого менеджер создаёт или меняет, должны лежать внутри его сетей.
- **Клиенты** — назначенные admin плюс созданные самим менеджером (назначаются ему
  при создании). Назначение на несуществующего клиента игнорируется и удаляется
  при обслуживании.
- **Логины прокси** — у proxy account есть `owner` (username панели или пусто = admin).
  Менеджер видит и меняет свои логины и логины, которыми пользуются только его
  клиенты. Созданный менеджером логин принадлежит ему.
- **Политики** — менеджер видит политики, на которые ссылаются его клиенты, и
  политики без клиентов. Менять или удалять может, только если все клиенты,
  ссылающиеся на политику, — его (для политики без клиентов условие выполнено).
  Новую политику создавать может.

Только admin: settings (включая upstream proxy, «запрещено для всех», скрытие адреса),
TLS-профили, expert squid.conf, пользователи панели и назначения, откат к прежней
ревизии, текст squid.conf и полные snapshots ревизий.

### Черновик и применение

Черновик остаётся одним. Изменение — объект (клиент, политика, логин), который
отличается в черновике от активной ревизии. Менеджер может применить или сбросить
черновик, только если каждое изменение в его области; иначе `403` с кодом
`draft_out_of_scope`, без перечня чужих объектов. Diff и preview менеджеру отдаются
структурированно и только по объектам области; текст squid.conf не отдаётся.

### Наблюдение

- Журнал запросов: события его клиентов. Неописанные источники (client_id пуст) —
  только с source IP внутри его сетей.
- Аудит: записи, где он actor, и записи об объектах его области.
- Обзор и статистика: агрегаты только по его клиентам. Состояние экземпляра
  (работает ли Squid, имя, время применения, свежесть журнала) видно всем ролям.
- Поиск и подсказки фильтруются сервером так же, как списки.

### Ответы вне области

| Ситуация | Ответ |
| --- | --- |
| Объект по id вне области (чтение или правка) | `404`, как для несуществующего |
| Endpoint только для admin | `403` `admin_required` |
| Политика видна, но у неё есть чужие клиенты | `403` `policy_shared_out_of_scope` |
| Адрес клиента вне сетей менеджера | `422` `source_outside_scope` |
| Адрес пересекается с клиентом вне области | `422` `source_overlap`, без имени чужого клиента |
| Имя логина уже занято чужим логином | `409` `username_taken`, без владельца |
| Применение или сброс черновика с чужими изменениями | `403` `draft_out_of_scope` |

Cursor журнала и аудита включает отпечаток области: смена области делает старый
cursor недействительным, а не расширяет выборку.

## Последствия

- Каждый handler, отдающий клиентов, политики, логины, события и аудит, фильтрует по
  области на сервере; скрытая кнопка в UI проверкой не считается.
- На каждый запрет из таблицы — негативный тест.
- Менеджеры видят факт занятости имени логина и пересечения адресов с чужим клиентом;
  это минимальная утечка, без имён и деталей.
- Менеджер с пустой областью видит только состояние экземпляра и справку.
