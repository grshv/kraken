# ADR 0006: один контейнер и один бинарник управления

Дата: 2026-10-27. Статус: **Accepted**.
Основание: владелец предложил объединить фронт/бэк со Squid и поручил обновить
документацию под этот вариант. Заменяет [ADR 0002](0002-restricted-local-runner.md).

## Решение

Один собственный image на базе pinned `ubuntu/squid`. Внутри Pebble управляет
отдельными процессами Squid и squid-control. Go-бинарник содержит static UI,
HTTPS/API, SQLite integration и внутренний модуль применения конфигурации.
Node нужен только при build. Host runner, Unix IPC web/runner, отдельные edge/web
контейнеры и systemd units приложения исключены. Compose содержит один сервис.
Docker socket/privileged/host namespace доступ не требуются.

## Почему

Единая установка и поставка проще исходной схемы. Локальный процесс Squid можно
проверять и перенастраивать из контейнера без выдачи Docker-полномочий приложению.
Pebble уже является supervisor базового image; его конкретный plan проверяется spike.

## Альтернативы и последствия

Отдельный host runner сильнее отделяет полномочия, но добавляет binary, IPC,
installation и recovery coordination. Для текущей поставки эта сложность отклонена.
Один контейнер разделяет жизненный цикл обновлений: upgrade панели прерывает Squid.
Падение только Go-процесса должно приводить к его независимому restart.
Web exploit потенциально затрагивает proxy config: внутренний модуль не sandbox.
Права процессов и signing CA всё равно должны быть минимальны и проверены.

## Проверка до реализации

Подтвердить UID/GID и право локального reload без root web; parse без изменения
live state; gate перед каждым запуском Squid; восстановление pending operations;
restart панели без остановки Squid; TLS capabilities и multi-stage build.
Файлы конфигурации и journal persistent, ключи вне image/Git. Обновление image
выполняется как совместно проверенный релиз с возможным downtime.

## Статус остальных решений

Упаковка принята. Выбор библиотек/версий Go, UI build, SQLite driver и точного
Pebble startup path остаётся проектным предложением до проверки. Этот ADR не
объявляет готовность приложения или поддержку TLS конкретным digest.
