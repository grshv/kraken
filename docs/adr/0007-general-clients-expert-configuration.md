# ADR 0007: клиенты прокси и экспертная конфигурация

Дата: 2026-10-27. Статус: Accepted по прямым уточнениям владельца.

## Уточнение продукта

VM — пример потребителя proxy. Клиентом может быть устройство, сервер, контейнер,
адрес, сеть или именованная группа адресов/CIDR. Тип host/network/group — метаданные
интерфейса, доступ определяет наблюдаемый source IP. NAT всё ещё может скрывать
разные устройства за одним адресом; название «группа» это не исправляет.

## Решение

Визуальные настройки Squid и экспертная пользовательская секция squid.conf
поддерживаются совместно. Snapshot хранит settings, configuration_mode и
expert_config. В structured действуют политики клиентов; в expert — пользовательский
ACL/http_access блок вместо них. Визуальные политики сохраняются для возврата.
Оба режима используют immutable revision → preview/diff → parse → apply/verify → rollback.

## Граница редактора

Это не unrestricted remote shell и не редактор произвольного host-файла.
Приложение владеет PID/log paths, listener ports, диагностическим 3130,
namespace sc_, canary header и внешним lifecycle. Include, executables/helpers,
смена UID/chroot и disk cache paths без provisioning запрещены.
По уточнению владельца 27.10.2026 listeners принадлежат установке: web draft и
операции над ревизиями не меняют их. Существующие установленные значения не
переписываются. Порты назначения/CONNECT редактируются как ACL. Итоговый полный
файл виден read-only без создания ревизии.
Остальные директивы проверяются реальным установленным Squid, а не объявляются
поддержанными лишь потому, что редактор принимает текст.

Common settings дают исходные параметры; эксперт может переопределять обычные
директивы. Пользовательские cache-правила идут до завершающего cache allow/deny,
поэтому исключения не затеняются глобальным переключателем.

## Последствия и ограничения

Экспертный режим предназначен доверенному администратору: cache_peer, ICAP и другие
сетевые функции меняют маршруты за пределами визуальной модели. Guard редактора
не является полной песочницей Squid и не заменяет egress firewall контейнера.
Произвольные исходные пароли администратора не попадают в конфигурацию автоматически.
Параметры внешних сервисов, которые сам администратор впишет в squid.conf,
считаются чувствительной конфигурацией. Они не должны попадать в parse-error logs:
подробный вывод Squid control command намеренно не возвращается.

HTTPS сайтов остаётся сквозным CONNECT. Helpers/auth/external ACL и
дисковый кеш требуют отдельных проверенных provisioning profiles; такие пути
не открываются универсальной текстовой командой. Это ограничение явно видно в UI.

## Проверка

Настройки и expert-профиль проходят настоящую Squid parse/сетевую suite.
Проверяются переход режимов, сохранность визуальных правил, запреты command/include,
защитный canary, diff/history/rollback, резервный cache-rule и восстановление после crash.

## Уточнение 29.10.2026: allowlist директив

Денайлист оказался неполным. На Squid 6.13 подтверждено: `err_page_stylesheet <файл>`
вставляет содержимое файла (например, TLS-ключа) в каждую страницу ошибки, видимую
любому клиенту прокси. Также проходили `"/path"`-параметры, `ftp_port`,
`deny_info /path` и `cache_peer` на metadata/loopback.

Граница редактора теперь задаётся allowlist директив в `src/internal/policy/settings.go`
(`expertDirectives`): ACL, http_access и близкие правила доступа, cache и refresh,
cache_peer, заголовки запроса, DNS, таймауты, лимиты, delay pools, `if/else/endif`.
Директива вне списка отклоняется при сохранении черновика. Дополнительно:

- запрещены параметры из файлов (`"/…"`, `parameters(…)`);
- `deny_info` принимает только `ERR_*`, `http(s)://` URL (с кодом 30x) или `TCP_RESET`;
- `cache_peer` — только IP-литерал вне защищённых сетей; private-адрес допустим
  только при `allow_private_destinations`; опции-пути запрещены;
- ошибка `squid -k parse` возвращает номер строки (в экспертной секции или итоговом
  конфиге), но не текст вывода Squid.

Расширение allowlist — изменение границы: директива добавляется вместе с тестом и
проверкой, что она не читает файлы, не открывает listener и не запускает процесс.
