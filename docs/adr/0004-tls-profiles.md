# ADR 0004: сквозной HTTPS и TLS-подключение к прокси

Дата: 2026-10-27. Статус: Accepted по прямому уточнению владельца.

## Контекст

Нужны управление доступом и диагностика без чтения содержимого HTTPS сайтов.
Шифрование подключения к самому прокси — отдельная задача.

## Решение

HTTPS панели обязателен. Клиент может подключаться к Squid по HTTP или TLS,
в зависимости от выбранного transport и установленного серверного сертификата.
HTTPS сайтов передаётся только через сквозной CONNECT: клиент проверяет исходный
сертификат сайта. Прокси не получает ключи TLS сайтов и не выпускает их сертификаты.
В модели остаётся единственный mode `tunnel`; отдельного issuer и доменных
исключений для изменения TLS-обработки нет. Экспертный редактор не открывает
управление TLS сайтов или служебными listeners.

## Последствия

Для HTTPS доступны host:port, исход запроса CONNECT и ограниченные счётчики.
URL-путь, HTTP-статус сайта и содержимое туннеля недоступны. HTTPS не кешируется.
Сертификаты панели и TLS listener прокси имеют обычный жизненный цикл server TLS.
Совместимость TLS к прокси проверяется отдельно для curl/APT и других клиентов.

Существующие tunnel snapshots читаются; прежние неиспользуемые поля исключены
из нового API. Compiler v4 требует новой проверки перед прямым apply старой
ревизии. Rollback ранее применённой ревизии компилируется текущим compiler.
