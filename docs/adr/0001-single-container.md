# ADR 0001: один узел и один контейнер

Статус: Accepted. Дата: 2026-10-27.

## Контекст

Kraken управляет исходящим доступом клиентов одного узла. Панель не должна стоять на
пути трафика и давать веб-процессу полномочия над Docker-хостом. Установка должна
оставаться одной командой без отдельных служб на хосте.

## Решение

- Один образ и один контейнер. Pebble (PID 1 после подготовки тома) запускает и
  перезапускает по отдельности два сервиса: `kraken squid-start` (Squid) и
  `kraken serve` (панель).
- Панель — Go-бинарник `kraken` со встроенным React UI (`go:embed`), HTTPS, API,
  модулем применения конфигурации (`internal/runtime`) и CLI оператора.
  Node нужен только при сборке.
- Данные — SQLite на томе `/var/lib/kraken`; внешней БД, очередей и сервисов нет.
- Один процесс `serve` владеет черновиком, ревизиями, операциями и сбором событий.
  CLI оператора (`docker exec … kraken`) — допустимый второй процесс с узким набором
  операций ([ADR 0005](0005-control-database.md)).
- Нет Docker socket, privileged mode, host network и shell API. Squid вызывается
  только с фиксированными argv, reload — через manager на loopback
  ([ADR 0010](0010-squid-manager.md)).

## Альтернативы

- Отдельный root-runner на хосте с Unix IPC: сильнее разделяет полномочия, но
  добавляет второй артефакт, systemd, протокол и согласование восстановления.
- Docker socket в панели или socket proxy: `exec` и `create` дают права на хост.
- Несколько контейнеров (edge, web, Squid): больше точек согласования при той же
  ценности для одного узла.
- PostgreSQL или Redis: инфраструктура без подтверждённой нужды.

## Последствия

- Трафик клиентов не проходит через панель: падение `serve` не останавливает Squid.
- Обновление образа перезапускает оба процесса и рвёт открытые туннели. HA нет.
- Модуль применения — часть процесса панели, а не граница изоляции: компрометация
  панели позволяет менять правила прокси. Риск снижают типизированная политика,
  allowlist expert-секции и разделение UID ([ADR 0009](0009-separate-squid-uid.md)).
- Второй экземпляр `serve` на той же БД не поддерживается.
