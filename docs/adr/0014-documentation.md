# ADR 0014: документация проекта

Статус: Accepted. Дата: 2026-10-29.

## Контекст

Агенты дописывали отчёты о сессиях в спецификации, статус «реализовано» расходился
в нескольких документах, шаблоны и вложенные инструкции не использовались, а
проверка не ловила расхождений.

## Решение

- Одна инструкция для людей и агентов — корневой `AGENTS.md` с таблицей «что
  меняется → какой документ обновить» и критериями готовности.
- Статус реализации и проверок — только в `docs/status.md`.
- Документы описывают текущее состояние; история — в git log. Планы, шаблоны и
  отчёты в репозитории не хранятся.
- ADR пишется только при смене инварианта или границы доверия. Принятый ADR не
  переписывается: заменяющий получает новый номер, старый — статус Superseded.
- `make docs-check` механически проверяет ссылки, реестр ADR, карту документов,
  отсутствие заголовков с датами в описательных документах и вложенных `AGENTS.md`.

## Последствия

Меньше документов и одно место для статуса. Механическая проверка не гарантирует
смысловой актуальности: ревью сверяет изменение кода с таблицей обновлений.
