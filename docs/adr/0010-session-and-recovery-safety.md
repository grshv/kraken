# ADR 0010: безопасные сессии и подтверждённое восстановление

Дата: 2026-10-27. Статус: Accepted — исправления по прямому поручению владельца.

## Контекст

Повторное ревью обнаружило deadlock SQLite на capacity audit, исчерпание
анонимного пула, незавершаемую first_run инициализацию, ложное подтверждение
rollback и неатомарную миграцию. Границы доверия и apply должны сохраняться при сбоях.

## Решение

Анонимный CSRF holder — Secure/HttpOnly/SameSite=Strict cookie с HMAC-SHA256,
случайным nonce и сроком 10 минут. Отдельный CSRF token выводится HMAC с другим
назначением. Ключ случайный, только в памяти текущего serve-процесса. Это не
авторизация: пользовательские сессии остаются в SQLite, reset атомарно отзывает их.
Старые анонимные DB rows читаются до истечения и удаляются обычной очисткой.

Внутри транзакции session audit использует то же соединение. Схема и version
ledger мигрируются в общей SQLite-транзакции, включая bootstrap DDL.

first_run с уже записанной LKG завершается только при совпадении journal/LKG и
active.conf. Offline recovery восстанавливает файлы, сохраняя pending journal.
Online recovery подтверждает reload и fingerprint перед terminal/rolled_back.
Ошибка оставляет recovery незавершённым, serve не начинает обслуживание; Pebble
может повторить запуск после готовности Squid. Безопасный squid-start использует
восстановленную предыдущую конфигурацию.

## Альтернативы и последствия

Eviction анонимных DB sessions вытеснял бы CSRF holders других посетителей;
фиксированный пул позволял блокировать новый вход. Stateless holder не требует
такого пула. Рестарт инвалидирует только анонимные holders: форма получает новый.
Защита от общего HTTP flood остаётся задачей сети; rate limits и Argon2 semaphore
действуют для login. Это не обещание доступности при произвольной нагрузке.
