# ADR 0005: документы как проверяемый контракт

Дата: 2026-10-27. Статус: Proposed.

## Контекст

Агенты должны видеть актуальные команды и границы, но большой prompt на каждый
сеанс повышает стоимость и риск противоречий.

## Решение

Короткий root AGENTS, карта docs, требования с acceptance IDs, C4-подобные схемы,
ADR, API contract, threat model и runbooks. Проверки ссылок/JSON запускаются одной
реальной командой и в CI. Task plan нужен сложной задаче, не каждой правке.

## Альтернативы

Один гигантский AGENTS — плохая навигация и быстрое устаревание.
Набор CLAUDE/Copilot/Cursor копий — дублирование без известной потребности.
Только README не покрывает apply failure и security invariants.

## Последствия

Нужно обновлять документы вместе с поведением. Локальная проверка не доказывает
смысловую согласованность, для неё нужны review и tests. Инструментальные адаптеры
добавляются по фактическому использованию, permissions и credentials остаются локальными.
