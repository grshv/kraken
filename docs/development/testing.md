# Проверки

## Команды

| Команда | Что проверяет | Когда обязательна |
| --- | --- | --- |
| `make docs-check` | Локальные ссылки, реестр ADR, карта docs, заголовки с датами, OpenAPI (operationId, path-параметры, CSRF), пример конфигурации, статьи справки, whitespace (`src/tools/docs-check`) | Любое изменение |
| `make check` | docs-check, typecheck и сборка web, vitest, `go test -race ./...`, `go vet`, `gofmt`, `git diff --check` | Любое изменение кода |
| `make integration` | Go-тесты с тегом `integration` на реальном Squid в образе `kraken:dev` | Изменения policy, runtime, deploy, auth |
| `make scan` | Уязвимости и секреты ([local-development](local-development.md#сканирование)) | Перед релизом; в CI — еженедельно |

`docs-check` — не полная валидация OpenAPI. Ни одна команда не заменяет
security-ревью. Браузерных e2e нет: владелец исключил Playwright, ключевые потоки
проверяются через API в integration.

## CI

GitHub Actions разделён по частям; каждый workflow запускается на push в `main` и в
PR только при изменении своих файлов.

| Workflow | Когда | Что делает |
| --- | --- | --- |
| `web.yml` | `src/web` | Сборка с CSP-хешами, vitest, `npm audit` production-зависимостей |
| `go.yml` | Go-код в `src` | gofmt, `go vet`, `go test -race`, `make scan-go` |
| `squid.yml` | `deploy/squid` | Squid из подписанного релиза на amd64 и arm64, образ панели с ним и `make integration`; из `main` — `ghcr.io/grshv/kraken-squid:<версия>` с provenance |
| `image.yml` | `src`, `deploy` (кроме Squid), Makefile; теги `v*` | Вызывает `go.yml` и `web.yml`; проверяет provenance закреплённого образа Squid; сборка на amd64 и arm64 с кешем слоёв, `make integration`, `make scan-sbom`; из `main` и тегов — multi-arch `ghcr.io/grshv/kraken` после Go- и web-тестов, provenance и SBOM attestations |
| `codeql.yml` | `src`; еженедельно | CodeQL для Go и TypeScript без тестовых файлов |
| `security.yml` | Еженедельно | `make scan-go`, `make scan-secrets`; для опубликованных `main` и `latest` — проверка attestation и `make scan-sbom` |
| `docs.yml` | Markdown, `docs`, `api`, справка | `make docs-check`, `git diff --check` |

GitHub сканирует секреты с push protection и выдаёт Dependabot alerts; обновления
зависимостей предлагает Renovate (`renovate.json`).

## Web unit-тесты

`npm --prefix src/web test` (vitest, без браузера) покрывает чистую логику экранов
в `src/web/tests/unit`: навигацию по ролям, автомат применения и причину запрета,
счётчик изменений черновика, правки и отмену изменений черновика, сети и домены,
итоговый список и метки «новый/изменён», запросы и фильтры журнала, объяснение
отказа, компактный период, предложения политики из уведомлений, названия действий
аудита, правила аккаунтов, единицы и правки настроек, вышестоящий прокси,
генератор CSP-хешей, фокус поля пароля, подпись устройства сессии, intent командной
палитры и контракты экранов с API.

## Integration

Каждый файл — отдельный `Test*` с шагами `t.Run`; верхнеуровневые тесты идут
параллельно, полный прогон — около 40 секунд. Пароли передаются только через
stdin; сертификаты генерируются в `t.TempDir()`.

| Тест | Что покрывает |
| --- | --- |
| `TestSmoke` | Неизвестный источник, весь веб, список доменов, IP-литерал, защитные запреты; HTTPS CONNECT с проверкой сертификата сайта; TLS к прокси и отказ plaintext; логины прокси: 407 и 403, разные логины за NAT, сброс и блокировка на живом соединении; настройки и expert-секция на реальном трафике; отказ запрещённых директив; номер строки parse; применение, идемпотентность, откат, восстановление после перезапуска; listeners не меняются черновиком и старой ревизией; `password-reset`; нет паролей в томе; изоляция UID |
| `TestNetwork` | Отказ для loopback, link-local, metadata, IPv4-mapped, 6to4, Teredo, NAT64 и частных адресов, в том числе через имена и CONNECT; DNS rebinding; `allow_private_destinations` |
| `TestApt` | `apt-get update/install` через HTTP и CONNECT из `ubuntu:26.04` на подписанном локальном репозитории; отказ без домена; ошибка подписи. Блок с настоящим архивом Ubuntu — `KRAKEN_TEST_REAL_APT=1` (DNS Docker Desktop и OrbStack отдаёт адреса `198.18.0.0/15`, которые прокси закрывает) |
| `TestOps*` | Копия и восстановление тома; замена сертификатов `cert install`; обновление образа на том же томе; заполненный диск без частичного применения; принудительная остановка |
| `TestDeploy*` | Быстрый старт на пустом каталоге чужого владельца без шагов с сертификатами; отказ для каталога с посторонними файлами |
| `TestLayout` | Содержимое тома, права tmpfs, пароль менеджера при перезапуске панели и контейнера |
| `TestBaseImage` | Версия и опции Squid, идентичность и версия образа, нет компилятора, UID, capabilities PID 1 и сервисов, reload через manager |
| `TestSquidParseMatrix` | `squid -k parse` набора снимков: схема 1 и 2, режимы, сети и IPv6, TLS и логины, expert-секция, upstream, кеш, крайние значения настроек |
| `TestFlows` | Отказ → объяснение → влияние черновика → применение; неописанный источник → клиент; менеджер не видит чужое и не применяет чужой черновик; сбой parse без изменения трафика, затем откат с записями в аудите |

## Обязательные негативные сценарии

Изменение затронутой области требует тестов:

- **Политика:** неизвестный и выключенный источник; точный домен, поддомен и похожее
  имя; пустой список; IP-литерал; частные, loopback, link-local, metadata, IPv6,
  IPv4-mapped, 6to4, Teredo; CONNECT на 22 и 25; manager недоступен клиенту;
  пересечение сетей отклоняется; правка одного клиента не расширяет доступ другого.
- **Expert:** директива вне allowlist, файл-параметр, peer во внутреннюю сеть, имена
  `sc_` отклоняются до parse.
- **Применение:** неверный конфиг, parse ok и reload fail, чужой отпечаток, сбой до и
  после каждой записи журнала, тот же ключ с другим телом, сбой отката, drift,
  перезапуск с незавершённым применением. Проверяется фактический доступ.
- **Вход:** нет сессии, CSRF или Origin — изменение отклонено; сброс и блокировка
  отзывают сессии.

Сетевые правила проверяются с отдельных source-адресов: запрос с localhost
доказывает только исключение localhost.
