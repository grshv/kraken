# Статус

Единственное место, где фиксируется, что реализовано, что проверено и что осталось.
Остальные документы описывают требуемое и устроенное поведение без статуса.
Это рабочая локальная версия, а не production-релиз.

## Известные ограничения

- Squid и Go работают от одного UID. Squid может читать БД и TLS-ключи; пока это
  закрыто только allowlist expert-секции (устраняется срезом 2 плана).
- `cache_peer` (expert и `upstream_proxy`) принимает только IP-литерал. Peer может
  маршрутизировать трафик за пределами визуальной модели; нужен egress firewall.
- Ошибка parse показывает номер строки, но не текст сообщения Squid.
- Один контейнер: обновление образа прерывает и панель, и прокси. HA нет.
- Принудительно закрывать открытые туннели нельзя; reload не гарантирует разрыв.
- UI будет переделан; текущий [interface](product/interface.md) описывает существующие экраны.

## План работ

Порядок согласован владельцем 29.10.2026: сначала изоляция секретов и сетевые
гарантии, затем упрощение; UI — после фиксации сценариев. Каждый пункт — отдельный
срез с приёмочными тестами; после среза строка переносится в «Реализовано».

| # | Срез | Критерии приёмки | Состояние |
| --- | --- | --- | --- |
| 2 | Разделение UID Squid и Go | Процесс Squid не может открыть SQLite панели и ключ панели (проверка `docker exec --user proxy`); proxy auth читает отдельный экспорт верификаторов; reload, apply, rollback и recovery работают как раньше. Spike выполнен: на Squid 6.13 `cache_object://127.0.0.1/reconfigure@<token>` через loopback 3131 перечитывает конфиг из процесса с другим UID, `kill -HUP` даёт EPERM. Решение — [ADR 0015](adr/0015-separate-squid-uid.md) | В работе |
| 3 | Сетевые запреты в smoke | С реальных source-адресов отклоняются IPv6 loopback/link-local, IPv4-mapped, 6to4, Teredo, private (при выключенной настройке), metadata; имя, резолвящееся во внутренний адрес; смена DNS-ответа между запросами (rebinding) не открывает внутренний адрес | Не начат |
| 4 | APT через прокси | `apt-get update` и `apt-get install` тестового пакета из локального подписанного репозитория через HTTP и через HTTPS CONNECT; проверка подписей включена; allowlist-клиент без домена репозитория получает отказ | Не начат |
| 5 | Ревизия expert-режима | Частые сценарии (кандидаты: upstream proxy, правила кеша пакетов) перенесены в типизированные настройки с тестами; expert остаётся аварийным режимом. Состав сценариев подтверждает владелец | Upstream proxy реализован (Go tests, мутационная проверка; integration — после сведения со срезами 2–4). Остальные сценарии ждут ответа владельца |
| 6 | Упрощение | Удалены пути совместимости, нужные только прежним локальным установкам (после проверки, что их LKG обновлены), и код без вызывающих; новых fault-injection тестов не добавляется, пока не закрыты 2–4 | Не начат |
| 7 | Новый UI | Сначала сценарии и макет экранов, согласованные владельцем; затем реализация одним срезом с e2e на ключевые потоки | Ждёт сценариев |

Эксплуатационные проверки, не блокирующие срезы выше:

| Проверка | Достаточный результат | Что пока не подтверждено |
| --- | --- | --- |
| Целевой Linux и сеть | Выбранная архитектура, опубликованные адреса, source IP/NAT, доверие сертификатам | Проверен только локальный Linux/arm64 |
| Заполненное хранилище | Ограниченный filesystem: отказ записи, перезапуск, целостность | ENOSPC инъецируется в коде, реальный полный диск не проверен |
| Эксплуатация | Копия /data и restore в новый volume, замена сертификата, обновление образа | [Процедуры описаны](operations/runbooks.md), прогона нет |

## Исключено владельцем

Аутентификация клиентскими сертификатами, расшифровка HTTPS сайтов, HA,
Kubernetes, multi-node, внешние runner/очереди/сервисы, замена SQLite, полная
реляционная переделка, zero-downtime обновления, горячий backup и backup UI/API,
центр выпуска сертификатов, SSO/IdP, bandwidth limits в UI, дисковый/package cache,
произвольные helpers, внешние alerts/экспорт, принудительное закрытие туннелей.
