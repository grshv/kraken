# Статус

Единственное место, где фиксируется, что реализовано, что проверено и что осталось.
Остальные документы описывают требуемое и устроенное поведение без статуса.
Это рабочая локальная версия, а не production-релиз.

## Известные ограничения

- Squid читает active config, верификаторы proxy accounts и ключ прокси; Go читает логи
  Squid через группу `proxy`.
- Volume, созданный сборкой до базовой схемы БД и разделения UID, не поддерживается:
  его нужно пересоздать (панель отказывается открывать несовместимую БД).
- `cache_peer` (expert и `upstream_proxy`) принимает только IP-литерал. Peer может
  маршрутизировать трафик за пределами визуальной модели; нужен egress firewall.
- Ошибка parse показывает номер строки, но не текст сообщения Squid.
- Один контейнер: обновление образа прерывает и панель, и прокси. HA нет.
- Принудительно закрывать открытые туннели нельзя; reload не гарантирует разрыв.
- UI проверен unit-тестами и API-тестами, без браузерных e2e: владелец исключил Playwright.

## План работ

Интерфейс сделан по прототипу [prototype/kraken-ui.html](product/prototype/kraken-ui.html)
(знак — [kraken-mark.svg](product/prototype/kraken-mark.svg)); решения — в [decisions](product/decisions.md).

Не реализовано в интерфейсе (доработать):

| Что | Почему нет | Что нужно |
| --- | --- | --- |
| Уведомления о неописанных источниках: «Просмотрено» и «Игнорировать» в списке клиентов | API есть (`source/<ip>`), в UI отметки ставятся только для отказанных доменов | Действия в группе «Неописанные источники» |
| Смена своего пароля диалогом из шапки | Пароль пользователя панели меняет только admin (`PATCH /users/{name}`) или CLI; своего эндпоинта смены с проверкой текущего пароля нет | Эндпоинт смены своего пароля и диалог |
| Группа «Свои у клиентов» в Политиках | В модели нет признака «своя»; сейчас — политика ровно одного клиента | Признак в модели или принятая эвристика |
| Проверка черновика (панель справа) и экран входа | В этом проходе не сверялись с прототипом | Сверка и доработка |

Новая задача добавляется сюда с критериями приёмки и после приёмки переносится
в «Реализовано».

Эксплуатационные проверки:

| Проверка | Достаточный результат | Что пока не подтверждено |
| --- | --- | --- |
| Заполненное хранилище | Ограниченный filesystem: отказ записи, перезапуск, целостность | ENOSPC на tmpfs проверен `TestOpsDiskFull`; полный loop/volume-диск на руках не проверялся |
| Эксплуатация | Копия тома и restore в новый volume, замена сертификата, обновление образа, принудительная остановка | Проверено `TestOps*` на `kraken:dev` (локальный OrbStack) |

## Перед распространяемым релизом

- Dependency/container/secret scans с разбором результатов (targets в Makefile нет). Ручной
  прогон trivy и govulncheck на образе Alpine: пакетов с уязвимостями нет, govulncheck —
  0 достижимых; Squid из исходников trivy не видит.
- Release notes: commit, image digest, architecture, schema, ограничения.
- Владелец выбирает лицензию и канал сообщений об уязвимостях.

## Исключено владельцем

Аутентификация клиентскими сертификатами, расшифровка HTTPS сайтов, HA,
Kubernetes, multi-node, внешние runner/очереди/сервисы, замена SQLite, полная
реляционная переделка, zero-downtime обновления, backup через UI/API,
центр выпуска сертификатов, SSO/IdP, bandwidth limits в UI, дисковый/package cache,
произвольные helpers, внешние alerts/экспорт, принудительное закрытие туннелей.
