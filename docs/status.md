# Статус

Единственное место, где фиксируется, что реализовано, что проверено и что осталось.
Остальные документы описывают требуемое и устроенное поведение без статуса.

Версия — **0.1.0**, первый релиз. Совместимость данных между версиями до 1.0 не
обещается: несовместимая БД не открывается, её нужно восстановить из копии
подходящей версии или пересоздать.

## Не подтверждено

- Импорт CA установки в браузеры вручную не проверялся.
- Несколько адресов хоста через `compose.override.yaml` проверены только
  `docker compose config`, без настоящих сетей.
- Заполнение настоящего тома: проверен ENOSPC на tmpfs (`TestOpsDiskFull`); проверку
  на loop-устройстве владелец пропустил.
- Настоящий архив Ubuntu через прокси проверяется только вручную
  (`KRAKEN_TEST_REAL_APT=1`): DNS Docker Desktop и OrbStack отдаёт адреса, которые
  прокси закрывает как частные.
- UI проверен unit-тестами и API-тестами, без браузерных e2e: владелец исключил
  Playwright.

## Известные ограничения

- Squid читает свой конфиг, верификаторы логинов прокси и ключ прокси; панель читает
  логи Squid через группу `proxy`.
- `cache_peer` (expert и `upstream_proxy`) принимает только IP-литерал. Peer может
  маршрутизировать трафик за пределами визуальной модели; нужен egress firewall.
- Ошибка parse показывает номер строки, но не текст сообщения Squid.
- Один контейнер: обновление образа прерывает и панель, и прокси. HA нет.
- Открытые туннели при отключении клиента не разрываются.
- Сертификаты не продлеваются автоматически: `kraken cert renew` раз в 397 дней.

## Исключено владельцем

Аутентификация клиентскими сертификатами, расшифровка HTTPS сайтов, HA,
Kubernetes, multi-node, внешние runner, очереди и сервисы, замена SQLite, полная
реляционная переделка, обновления без простоя, копия через UI и API, центр выпуска
сертификатов, SSO и IdP, лимиты полосы в UI, дисковый и пакетный кеш, произвольные
helpers, внешние уведомления и экспорт, принудительное закрытие туннелей, лицензия
и канал сообщений об уязвимостях (личный проект).
