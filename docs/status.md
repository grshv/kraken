# Статус

Единственное место, где фиксируется, что реализовано, что проверено и что осталось.
Остальные документы описывают требуемое и устроенное поведение без статуса.
Это рабочая локальная версия, а не production-релиз.

## Известные ограничения

- Squid читает active config, верификаторы proxy accounts и ключ прокси; Go читает логи
  Squid через группу `proxy`.
- Volume, созданный сборкой до базовой схемы БД и разделения UID, не поддерживается:
  его нужно пересоздать (панель отказывается открывать несовместимую БД).
- `cache_peer` (expert и `upstream_proxy`) принимает только IP-литерал. Peer может
  маршрутизировать трафик за пределами визуальной модели; нужен egress firewall.
- Ошибка parse показывает номер строки, но не текст сообщения Squid.
- Один контейнер: обновление образа прерывает и панель, и прокси. HA нет.
- Принудительно закрывать открытые туннели нельзя; reload не гарантирует разрыв.
- UI проверен unit-тестами и API-тестами, без браузерных e2e: владелец исключил Playwright.

## План работ

Интерфейс сделан по прототипу [prototype/kraken-ui.html](product/prototype/kraken-ui.html)
(знак — [kraken-mark.svg](product/prototype/kraken-mark.svg)); решения — в
[decisions](product/decisions.md). Каждый пункт — отдельная задача с приёмочными
тестами; после неё строка переносится в «Реализовано».

| Задача | Критерии приёмки | Состояние |
| --- | --- | --- |
| Устойчивость управляющей БД | Пулы чтения и записи, таймауты запросов с ответом `storage_busy`, отметка сессии не чаще раза в минуту, аудит 3 года; при нехватке места сбор событий останавливается, а применение отвечает `storage_full` до записи | Не начат |
| Integration на Go | smoke, network, apt, ops — Go-тесты с тегом `integration`, сценарий в сценарий; Python удалён | В работе |
| Ключевые потоки на образе | Отказ → разрешить → применить; клиент из неописанного IP; менеджер не видит чужое и не применяет чужой черновик; сбой применения с откатом — через API на реальном Squid | Не начат |

Эксплуатационные проверки, не блокирующие срезы выше:

| Проверка | Достаточный результат | Что пока не подтверждено |
| --- | --- | --- |
| Целевой Linux и сеть | Выбранная архитектура, опубликованные адреса, source IP/NAT, доверие сертификатам | Проверен только локальный Linux/arm64 |
| Заполненное хранилище | Ограниченный filesystem: отказ записи, перезапуск, целостность | ENOSPC на tmpfs проверен `ops.py`; полный loop/volume-диск на руках не проверялся |
| Эксплуатация | Копия /data и restore в новый volume, замена сертификата, обновление образа, принудительная остановка | Проверено `ops.py` на `kraken:ops` (локальный OrbStack); реальная клиентская установка и restore не проводились |

## Перед распространяемым релизом

- Dependency/container/secret scans с разбором результатов (targets в Makefile нет).
- Release notes: commit, image digest, architecture, schema, ограничения.
- Владелец выбирает лицензию и канал сообщений об уязвимостях.

## Исключено владельцем

Аутентификация клиентскими сертификатами, расшифровка HTTPS сайтов, HA,
Kubernetes, multi-node, внешние runner/очереди/сервисы, замена SQLite, полная
реляционная переделка, zero-downtime обновления, горячий backup и backup UI/API,
центр выпуска сертификатов, SSO/IdP, bandwidth limits в UI, дисковый/package cache,
произвольные helpers, внешние alerts/экспорт, принудительное закрытие туннелей.
