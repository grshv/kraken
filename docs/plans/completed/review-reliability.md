# Исправления повторного ревью

Дата: 2026-10-27. Статус: Completed.

Критерии приёмки:

- Анонимные запросы формы входа не занимают SQLite sessions и не блокируют вход.
  Подписанный CSRF holder проверяет целостность, срок и ключ текущего процесса.
- Переполнение авторизованных сессий возвращает ошибку и пишет audit без deadlock.
- Первичная инициализация возобновляется после ошибки каждой durable записи,
  включая промежуток между LKG и terminal marker; несовпадение данных отклоняется.
- Offline recovery готовит конфигурацию к запуску, но не подтверждает live rollback.
  Ошибка reload/verify сохраняет pending journal; успех закрывает recovery.
- Изменения схемы, перенос данных и версия миграции атомарны. Ошибка не оставляет
  промежуточную таблицу, старые данные сохраняются, повторный запуск успешен.
- Истёкшая сессия при GET и mutation возвращает работоспособную форму входа без
  reload страницы. Ошибочный пароль допускает следующую попытку.
- Панель доступна через опубликованный Docker-порт: слушает :8443 внутри
  контейнера, host binding ограничивается Compose.
- Обновлены спецификации/ADR; проходят race/vet, docs, image, real-image и browser tests.

Подтверждено:

- Go race tests и vet, frontend typecheck/build, docs-check и patch check.
- Ошибки каждой записи first_run, несовпадающие journal/LKG, offline/online
  recovery и отказы reload/fingerprint проверены на временных каталогах.
- SQLite trigger прерывает миграцию после DDL и переноса audit, перед version
  insert: предыдущая схема/данные сохранены, повторная миграция успешна.
- 300 anonymous holders не создают DB sessions; вход после потока успешен.
  Полный авторизованный пул возвращает 503, capacity audit доступен и ложный
  успешный login не записывается. Проверены подпись, expiry и смена ключа.
- make image и real-image smoke (Linux/arm64) прошли. Дополнительно незавершённый
  journal с отличающимися previous/candidate переживает restart контейнера:
  оба startup-процесса восстанавливают прежние ACL, journal terminal/rolled_back,
  реальный запрос ранее запрещённого candidate клиента разрешён previous.
- Playwright: 4 сценария прошли, включая GET/mutation expiry и повторный вход
  после неверного пароля без reload страницы.

Проверки выполнялись в изолированных контейнерах/временных БД. Рабочая установка,
её пароль, сертификаты и volume не изменялись. Частично применённую миграцию
старой версии автоматический repair не исправляет; нужен анализ/restore.
Остаток проверок перед установкой и выпуском ведётся только в [roadmap](../roadmap.md).
