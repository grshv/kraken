# План без лишней инфраструктуры

Пересмотрено 27.10.2026 после уточнения владельца о масштабе backup/restore.
Задача продукта: управлять доступом клиентов через Squid и объяснять наблюдаемые
результаты. Один контейнер, один Go executable со встроенной панелью, Squid и SQLite.

Этот документ — текущий приоритет работ. Списки «следующий этап» в завершённых
планах — история на дату выполнения, а не дополнительные обязательства.
[Фактические проверки](../research/image-compatibility.md) и
[требования](../product/requirements.md) сохраняют силу. Упрощение поставки не
отменяет защитные ACL, безопасный пароль и проверяемое применение конфигурации.

## Уже работает

- HTTPS-панель, bootstrap, hash пароля, sessions/CSRF и CLI password-reset.
- Клиенты/IP/CIDR/группы, all_web/allowlist, visual settings и guarded expert config.
- Draft, diff, реальный parse, apply, fingerprint verification, LKG, rollback,
  durable journal и recovery; независимый restart процессов.
- История запросов, client/failure filters, cursor, bounded retention, stale/gap,
  аудит. Новая подсистема истории не требуется.
- Multi-stage image, single-service Compose, pinned dependencies/images,
  локальные проверки и workflows docs/runtime. Наличие workflow не доказывает,
  что он уже успешно выполнился на целевой архитектуре.

## Что действительно остаётся

| Задача | Зачем | Минимальное достаточное решение | Приоритет |
| --- | --- | --- | --- |
| Проверить обычного клиента, особенно APT | Python HTTP fixture не доказывает совместимость APT | Один тест update/download с проверкой подписей/хэша; короткие примеры curl/APT | До обычного использования |
| Установка на целевой Linux/архитектуре | Локально проверен Linux/arm64, ОС узла не задана | Собрать/проверить один выбранный image, настроить source IP и published ports; не строить матрицу всех ОС | До установки |
| Network boundaries и private destinations | Ошибка может открыть доступ к внутренним адресам | Небольшой набор реальных deny tests: loopback/link-local/metadata, IPv6/mapped, смена DNS на запрещённый IP | До заявления о соответствующей защите; не снимать существующие ACL |
| Развёртывание и обновление | Нужны воспроизводимые действия оператора | Свести текущие Compose-команды в одну инструкцию, записать image ID/digest и совместимость схемы; предупредить об обрыве CONNECT при recreate | До установки/обновления |
| Копирование и восстановление данных | Сохранить DB и runtime одного состояния | Остановить единственный контейнер, скопировать /data и отдельно внешние TLS mounts/Compose settings; один restore в новом volume | Короткая эксплуатационная задача, без backup API/UI |
| Серверные сертификаты | Нужны рабочие SAN/trust и замена истекающих ключей | Файлы вне image, проверка пары key/cert, прав UID 13 и доверия; остановка/замена/запуск с допустимым перерывом | До реальной TLS-установки; web PKI не требуется |
| Критические сбои хранилища | Уже есть ENOSPC injection и SIGKILL, но это не настоящий полный диск | Один изолированный сценарий заполнения ограниченного filesystem, отказ записи/повторный старт/rollback; не создавать лабораторию отказов питания | До утверждения готовности к таким отказам |
| Место на диске | История и raw logs уже ограничены, но bytes/watermark не реализованы | Проверка свободного места оператором/существующим мониторингом; при реальной необходимости небольшой warning в панели | Не нужен отдельный storage manager |
| Проверка перед выпуском | Не пропустить известную проблему зависимости или образа | Прогнать имеющиеся проверки и отдельные dependency/container/secret scans, разобрать результаты; сканеры пока не реализованы в Makefile | Перед распространяемым релизом |
| Описание релиза | Нужно понимать, что установлено и как вернуться | Короткие release notes: commit/image, architecture, schema, совместимость, известные ограничения | При первом распространяемом релизе |
| Регрессии API/UI | Есть ручные Go/TS types и структурный docs-check | Дополнять HTTP/browser tests по меняемым контрактам; при дрейфе добавить готовую schema validation в текущие проверки | Вместе с изменениями; не строить генератор платформы |

При выборе конкретного узла уточняются его ОС/архитектура, management/client сети,
NAT/source IP и серверные сертификаты. Proxy settings не запрещают прямой egress:
если запрет нужен, его задают на сетевой границе вне панели. Это не новая функция
управления host firewall/Docker из web-приложения.

## Реализованы users/roles и proxy login

По уточнению владельца — только admin и viewer. Admin управляет всей панелью,
viewer читает состояние/события/аудит. Users management, session revoke и last-admin
guard реализованы в существующих Go/API/SQLite/UI, без отдельного сервиса.

Proxy accounts отдельные от users, только Argon2id PHC hashes. Auth-bound clients
используют TLS, IP/CIDR + exact username и свои policies; разные логины могут
делить адреса за NAT. Managed Basic helper и uncached generation state check
обеспечивают reset/disable при кешировании credentials Squid. Expert mode с
включёнными auth clients запрещён; arbitrary exec не открыт.

UI переведён по запросу владельца на shadcn/ui (Radix/New York): Sidebar/Sheet,
готовые формы, таблицы, диалог и вкладки. Компоновка проверена с UI/UX Pro Max;
дополнительные пояснения раскрываются по запросу. [Компоненты и оформление](../product/interface.md).
[Решение и границы](../adr/0012-local-users-and-proxy-passwords.md).

## Исключено владельцем из объёма

Аутентификация клиентскими сертификатами исключена владельцем.
Прочие предложенные расширения не оставляем в отложенном backlog:
дополнительный поиск/долгосрочную аналитику, отдельную certificate UI/автоматический выпуск,
IDN normalization, новые private-resource формы, SSO/OIDC/LDAP, bandwidth limits,
новые peers/helpers возможности, внешние alerts/экспорт, дисковый/package cache,
точечное завершение открытых туннелей. Уже реализованные настройки, guarded expert
config, история и фильтры сохраняются. Серверные сертификаты и доверие для proxy
TLS настраиваются как необходимые части этих функций, без добавления центра
выпуска сертификатов. Базовые проверки безопасности и инструкции установки сохраняются.

## Исключённые архитектурные расширения

- HA, кластеры, multi-node control, Kubernetes, внешнюю очередь и отдельный runner:
  исключены прямым уточнением владельца.
- Переезд с SQLite и полную реляционную переделку: текущая модель не показала
  необходимости такого изменения. Миграции добавляются под конкретные данные.
- Горячий backup, поколения архивов, backup manifests, scheduler и web export:
  остановленная копия состояния достаточна при допустимом перерыве.
- Zero-downtime upgrades и hot rotation сертификатов: сначала обычная замена с
  понятным окном обслуживания, без обещания сохранить CONNECT при recreate.
- Бесконечную «полную матрицу» всех ОС, отказов питания и вариантов Squid:
  сохраняем проверки поддерживаемых сценариев и конкретных границ безопасности.
- Собственную платформу release/provenance. Для локальной поставки достаточно
  образа, зафиксированной версии и инструкции; SBOM/signing добавляются под
  требования распространения/CI, без собственного сервиса.
- Новые агентские документы/адаптеры на каждый случай: AGENTS, исходные specs,
  ADR существенных решений и проверяемые команды уже есть. Не создавать файлы
  только ради полноты структуры. Лицензию и security contact выбирает владелец
  перед публикацией, не разработчик автоматически.

## Оставшиеся практические проверки

Настоящий APT с нужным transport, один целевой Linux/architecture, адресные
private/IPv6/DNS и storage failure tests, короткие процедуры volume copy/cert
replacement/update. Успешный Python HTTP smoke не является проверкой APT.
Уже реализованные users/roles/proxy login и UI не нужно разрабатывать повторно.
Исключённые расширения не возвращаются автоматически из старых specs.
