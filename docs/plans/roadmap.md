# Текущий план

Актуализировано: 28.10.2026. Продукт — управление доступом через Squid и диагностика.
Один контейнер, Go со встроенным React UI, Squid и SQLite. Этот файл — единственный
список оставшихся работ; [завершённые планы](completed/) сохраняют критерии и
результаты, но не задают новый backlog. Фактические границы проверок —
[capability report](../research/image-compatibility.md).

## Реализовано и проверено локально

- HTTPS-панель, bootstrap, Argon2id, sessions/CSRF, CLI password-reset.
- Пользователи admin/viewer, блокировка, отзыв сессий и защита последнего admin.
- Отдельные proxy accounts; парольная аутентификация по TLS, IP/CIDR + username.
- Клиенты/сети/группы, all_web/allowlist, настройки и защищённая expert-секция.
- Черновик, настоящий diff, parse, apply, fingerprint, LKG, recovery и rollback.
- История запросов с серверными фильтрами и cursor, аудит, ограниченное хранение.
- Обзор: подтверждённые правила, состояние Squid, источники и группы проблем;
  периоды от 15 минут до 30 дней, переход в отфильтрованный журнал.
- Общие компоненты shadcn/ui, светлая начальная и ручная тёмная тема,
  Inter 14/16px, единые редакторы и иерархия заголовков.
- Сборка образа Linux/arm64, Go race/vet, реальные Squid smoke и 20 браузерных
  сценариев. Локальное обновление сохранило действующие правила, черновик и историю.

Это рабочая локальная версия, не подтверждение готовности любой установки.

## Осталось перед обычным использованием

| Проверка | Достаточный результат | Что пока не подтверждено |
| --- | --- | --- |
| Настоящий APT | update и download с проверкой подписей/хэшей через нужный transport | HTTP/HTTPS fixtures не заменяют APT |
| Целевой Linux и сеть | Один выбранный image/architecture, опубликованные адреса, source IP/NAT и доверие сертификатам | Узел установки и клиентское окружение не выбраны; локально проверен Linux/arm64 |
| Дополнительные сетевые запреты | Адресные deny tests для IPv6/mapped, private/link-local/metadata и смены DNS на запрещённый адрес | Существующие ACL и smoke не покрывают все эти случаи |
| Реально заполненное хранилище | Изолированный ограниченный filesystem: отказ записи, перезапуск и сохранность согласованного состояния | ENOSPC injection и SIGKILL уже проверены; настоящий полный диск — нет |
| Эксплуатационные инструкции | Прогнать остановленную копию /data и restore в новом volume, замену server cert и обновление образа | [Процедуры описаны](../operations/runbooks.md), полного прогона нет |

Следующий технический срез — APT на изолированной тестовой установке.
Выбор реального узла нужен только для проверки его deployment; он не блокирует
остальные локальные проверки. Сетевой запрет обхода proxy задаётся вне панели:
proxy settings сами по себе не запрещают прямой egress.

## Только перед распространяемым релизом

- Выполнить dependency/container/secret scans и разобрать результаты. Готовых
  targets сканирования в Makefile пока нет.
- Записать commit/image, architecture, schema, совместимость и ограничения релиза.
- Владелец выбирает лицензию продукта и канал сообщений об уязвимостях.

Регрессии проверяются при изменении соответствующего поведения; отдельной задачи
переписать API types, SQLite или тестовую платформу нет. Свободное место пока
контролирует оператор; новый storage manager и warning не входят в план.

## Исключено владельцем

Клиентские сертификаты для аутентификации, расшифровка HTTPS сайтов, HA,
Kubernetes, multi-node, внешние runner/очереди/сервисы, замена SQLite и полная
реляционная переделка, zero-downtime обновления. Также исключены горячий backup,
backup UI/API/scheduler, центр выпуска сертификатов, SSO/IdP, bandwidth limits,
дисковый/package cache, произвольные helpers, внешние alerts/экспорт и принудительное
завершение отдельных туннелей. Новые агентские документы ради структуры не нужны.

Уже реализованные настройки, guarded expert config, фильтры и агрегаты retained
history сохраняются. Серверные сертификаты, их доверие и простая остановленная
копия состояния — эксплуатация существующих функций, без новых подсистем.
