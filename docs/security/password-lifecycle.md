# Пароль администратора и CLI reset

Исходный пароль нужен только кратковременно при вводе/проверке в памяти.
Приложение не сохраняет его в DB, конфигурации, временных файлах, env, argv,
логах или audit. В таблице users есть username и password_hash; поля plaintext
password и ключа для «расшифровки пароля» нет.

Новый verifier — Argon2id в PHC формате с уникальной случайной солью и явными
параметрами m=19456 KiB, t=2, p=1, 32-byte output. Соль и параметры не являются
секретным исходным паролем. Это односторонний hash, не шифрование с обратным ключом.
Старые argon2id$salt$hash записи первого среза продолжают проверяться, без сохранения
или восстановления исходного пароля. Хэширование не отменяет риск подбора слабого
пароля; minimum input — 12 bytes, maximum — 1024 bytes без молчаливого усечения.
Основание: [OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html),
проверено 27.10.2026.

## Локальный сброс

Из корня репозитория:

```sh
make password-reset
```

Helper спрашивает username и новый пароль дважды без echo, затем передаёт пароль
только по stdin в одноразовый container с тем же named volume, UID/GID 10013:10013.
Панель может быть остановлена или работать. Текущий/старый пароль не нужен.
Helper не пишет credential file и не печатает новый пароль.

Прямой CLI для работающего контейнера:

```sh
docker compose -f deploy/compose.yaml exec --user 10013:10013 kraken \
  kraken password-reset --username admin
```

Сам Go CLI скрывает ввод на терминале и просит подтверждение. В non-interactive
режиме нужен явный --password-stdin; пароль не передаётся аргументом или env.
Не подставляйте его литералом в shell-команду, которая сохранится в history.
Прямой CLI без --password-stdin на pipe возвращает понятную ошибку.

## Атомарность

Reset обновляет password_hash, удаляет все sessions данного пользователя и пишет
безопасный audit event в одной SQLite транзакции. Неизвестного пользователя
reset не создаёт. Невалидный пароль/ошибка DB откатывают транзакцию.
Вход перед выпуском session повторно сравнивает актуальный verifier в той же
транзакции, что вставляет session: запрос со старым hash после reset не может
создать позднюю действующую сессию. Уже выполняющийся авторизованный запрос может
завершиться; следующие запросы со старым token получат 401.

## Проверки

Unit tests: salted PHC, отказ для формата без версии и параметров, неправильный пароль, malformed verifier, отсутствие
plaintext в хранилище, отзыв сессий, гонка stale-login/reset и неизвестный username.
Network suite выполняет настоящий CLI reset на отдельном тестовом volume, проверяет
невалидность старой сессии/пароля и вход с новым. Password этой suite создаётся
случайно в памяти, по stdin передаётся CLI и никогда не печатается.
Browser fixtures также создают одноразовый account в памяти, без credential files.
