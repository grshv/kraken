# Аутентификация и сертификаты

## Пользователи панели

Первого администратора создаёт оператор локально; публичной регистрации и пароля
по умолчанию нет:

```sh
docker exec -it kraken kraken bootstrap --username admin
```

Пароль вводится без эха или передаётся `--password-stdin`; аргументом, через env и
файлы — никогда. Роли — администратор и менеджер
([ADR 0007](../adr/0007-admin-and-manager-roles.md)). Права проверяет сервер на
каждом запросе; объект вне области — 404, ручка только для администратора —
`403 admin_required`.

## Пароли

- Verifier — Argon2id PHC: `m=19456 KiB, t=2, p=1`, соль 16 байт из `crypto/rand`,
  выход 32 байта ([OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)).
  Другие форматы не принимаются.
- При проверке параметры PHC ограничены (`memory` ≤ 38912 KiB, `iterations` ≤ 4,
  `parallel` ≤ 2): подменённый verifier не заставит панель выделить сотни мегабайт.
- Длина пароля — 12–1024 байт, без молчаливого усечения.
- Исходный пароль не сохраняется в БД, конфигурации, временных файлах, env, argv,
  логах и аудите. Восстановить пароль из хеша нельзя.

### Смена и сброс

- Свой пароль пользователь меняет диалогом в панели (`PUT /session/password`): нужен
  текущий пароль, не больше 5 попыток в минуту на учётную запись. Hash заменяется,
  только если не изменился с момента проверки (иначе `409 credentials_changed`);
  текущая сессия остаётся, остальные завершаются; аудит — `change_password` или
  `change_password_failed`.
- Оператор сбрасывает пароль командой, в том числе при остановленной панели:

  ```sh
  docker exec -it kraken kraken password-reset --username admin
  printf 'новый-пароль\n' | docker exec -i kraken kraken password-reset --username admin --password-stdin
  ```

  Сброс в одной транзакции меняет hash, удаляет все сессии пользователя и пишет
  аудит. Неизвестного пользователя он не создаёт. Вход, начатый до сброса, сверяет
  hash в транзакции создания сессии и не выпускает её.

## Сессии

- Токен случайный, в cookie `__Host-session; Secure; HttpOnly; SameSite=Strict;
  Path=/`; в БД — только хеш. Срок — 12 часов, бездействие — 30 минут, не больше
  256 сессий ([ADR 0006](../adr/0006-panel-sessions.md)).
- Каждое изменение, включая выход, требует CSRF-токен и совпадение Origin с
  `KRAKEN_PUBLIC_ORIGIN`.
- Форма входа получает подписанный CSRF holder на 10 минут без записи в БД. При 401
  UI берёт новый holder через `GET /session` и возвращает форму входа без
  перезагрузки.
- Вход: не больше 5 попыток в минуту с адреса на учётную запись и 20 — на учётную
  запись (скользящее окно); Argon2id — не больше двух одновременно. Ошибка входа —
  общее сообщение; бессрочной блокировки нет.
- Пользователь видит свои сессии (`GET /users/{name}/sessions`: начало, адрес и
  User-Agent при входе, последняя активность) и завершает одну или все, кроме
  текущей; администратор — сессии любого пользователя. ID сессии в API — первые
  8 байт SHA-256 от хеша токена; по нему нельзя восстановить токен. Адрес — peer
  TCP-соединения без доверия `X-Forwarded-For`; User-Agent без управляющих символов,
  до 256 символов. Завершение пишется в аудит (`revoke_session`, `revoke_sessions`).
- Сброс пароля, смена роли и блокировка завершают сессии пользователя; смена области
  менеджера — нет.

## Логины прокси

Логин прокси — отдельная учётная запись для подключения клиента, не вход в панель
([ADR 0008](../adr/0008-proxy-logins.md)).

- В БД только Argon2id PHC; прежний пароль не выдаётся.
- Пароль передаётся только по TLS к прокси (3129). Адреса и логин вместе
  определяют клиента; доступ — его режим и список.
- Squid держит учётные данные в памяти и передаёт helper через stdin/stdout; на
  диск, в argv, env и логи пароль не попадает. Helper читает только экспорт
  верификаторов в tmpfs и не логирует запросы.
- Basic TTL — 1 секунда; generation ACL на каждом разрешаемом запросе без кеша
  сверяет verifier и включённость, поэтому сброс и блокировка действуют сразу.
  Начатые запросы и открытые туннели могут завершиться.
- `auth_param` и `external_acl_type` в expert-секции запрещены; клиенты с логином
  не совмещаются с expert-режимом.

## Серверные сертификаты

Панель и TLS-прокси используют сертификаты, которые установка выпускает сама, или
свои, установленные `kraken cert install`
([ADR 0013](../adr/0013-install-and-certificates.md)). Если в `certs/` нет ни одного
из `panel.*` и `proxy.*`, `serve` при старте выпускает:

| Файл | Что | Права |
| --- | --- | --- |
| `ca.crt`, `ca.key` | CA установки: ECDSA P-256, 10 лет, `pathlen 0`, критичные name constraints на имена установки | 0644; ключ 0600 `kraken` |
| `panel.crt`, `panel.key` | Сервер панели: 397 дней, `serverAuth`, SAN — имена установки | 0644; ключ 0600 `kraken` |
| `proxy.crt`, `proxy.key` | Сервер TLS-прокси 3129, тот же SAN | 0640, группа `proxy` |

Имена установки: `localhost`, `127.0.0.1`, `::1`, host из `KRAKEN_PUBLIC_ORIGIN`,
адреса `KRAKEN_MANAGEMENT_BIND` и `KRAKEN_PROXY_BIND` (кроме `0.0.0.0`) и
`KRAKEN_CERT_NAMES` (DNS или IP; wildcard, URL и порт отклоняются). Из-за name
constraints ключ CA не может выпустить доверенный сертификат для другого имени,
поэтому хранится на томе и позволяет продлевать сертификаты без нового импорта.
Неполный набор файлов не перезаписывается: старт останавливается с перечнем
недостающих.

| Действие | Команда |
| --- | --- |
| Получить CA для импорта | `docker exec kraken kraken cert ca > kraken-ca.crt` |
| Перевыпустить под текущие имена | `docker exec kraken kraken cert renew && docker compose restart kraken` |
| Поставить свой сертификат | `cat panel.crt panel.key \| docker exec -i kraken kraken cert install panel` (или `proxy`), затем `docker compose restart kraken` |

- `cert renew` при имени вне constraints создаёт новый CA, его нужно импортировать
  заново. `cert renew` заменяет и установленный свой сертификат.
- `cert install` принимает сертификат, промежуточные и ключ одним PEM через stdin,
  проверяет пару, срок, `serverAuth` (или отсутствие EKU), SAN и что это не CA,
  затем пишет файлы с правами из таблицы; при ошибке файлы не меняются.
- Горячей замены нет: новые файлы читаются после перезапуска контейнера.
  Автоматического продления нет.
- API `/certificates` отдаёт subject, SAN, issuer, fingerprint и срок, без ключа;
  UI предупреждает за 30 дней до истечения.
- HSTS панели — `max-age=31536000` без `includeSubDomains` и `preload`.
- В инструкциях нет `curl -k` и отключения проверки: правильный путь — импорт CA.
  Публичный CA можно раздавать, ключ — никогда.

## Конфиденциальность журнала

Для HTTPS известны домен, порт, результат туннеля, длительность и байты; путь,
заголовки и тела — нет. Для HTTP query, `Authorization`, cookies и тело не
сохраняются; путь URL в журнал панели тоже не попадает. Сырой access.log Squid
содержит URL и остаётся чувствительным файлом с правами `proxy` 0640.
