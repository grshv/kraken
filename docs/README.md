# Документация Kraken

Каждый документ отвечает на один вопрос и описывает текущее состояние; история — в
git log. Что реализовано и проверено — только в [status](status.md). Какой документ
обновлять вместе с кодом — таблица в [AGENTS.md](../AGENTS.md#что-обновлять-вместе-с-кодом).
`make docs-check` требует, чтобы каждый Markdown-файл в `docs/` был указан здесь.

## Термины

| Термин | Значение |
| --- | --- |
| Установка | Один контейнер Kraken с томом `/var/lib/kraken` |
| Панель | Веб-интерфейс и API (`kraken serve`) |
| Оператор | Тот, кто управляет установкой командой `docker exec … kraken` |
| Администратор, менеджер | Роли пользователей панели; область менеджера — его сети, клиенты и логины прокси |
| Клиент | Устройство, адрес, сеть или группа адресов, которым выдаётся доступ |
| Неописанный источник | Адрес, приславший запрос, но не описанный ни одним клиентом |
| Политика | Именованный набор доменов; клиент подключает любое число политик |
| Свои домены | Домены, заданные прямо у клиента |
| Итоговый список | Объединение своих доменов клиента и его политик |
| Режим доступа | Свойство клиента: список доменов, весь веб или нет доступа |
| Подключение | HTTP (3128) или TLS (3129) с логином прокси |
| Логин прокси | Логин и пароль для подключения клиента к прокси; не вход в панель |
| Запрещено для всех | Домены, закрытые для всех клиентов в любом режиме |
| Защитные запреты | Опасные порты, manager Squid и внутренние адреса; действуют всегда |
| Черновик | Несохранённые в трафик правки конфигурации |
| Ревизия | Неизменяемый снимок конфигурации с номером `r-<N>` |
| Применение | Операция, которая делает ревизию действующей с проверкой и откатом |
| LKG | Последняя рабочая конфигурация (last known good) |
| Expert-секция | Текст squid.conf с директивами из allowlist вместо визуальных правил |

## Правила

- Требования описывают ожидаемое поведение, архитектура — как устроено, ADR — почему,
  runbooks — что делать оператору.
- Термины — из таблицы выше; идентификаторы кода и API — по-английски в `code`.
- Даты допустимы только в decisions и ADR.
- Внешний факт сопровождается первичной ссылкой.
- `make docs-check` не ходит в интернет и не проверяет внешние ссылки.
